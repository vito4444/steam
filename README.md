# Undertown

A top-down colony builder whose recurring pressure is an imperial **audit** rather than a
natural disaster. Above ground you run a lawful border town and pay your tax; below ground
you dig chambers and produce contraband.

The inspector does not need to find your tunnel. He only needs to notice that your timber
does not add up.

- Engine: Unity 6.3 LTS (`6000.3.22f1`), Mono scripting backend
- Target: Windows x64, built from a headless Linux machine
- Design document: [docs/GDD.md](docs/GDD.md)
- Visual targets and progress: [docs/visual-progress.md](docs/visual-progress.md)

## The hook

You cannot produce something from nothing. Divert a sack of grain to the still and there are
three stories you can tell, each of which breaks a different check:

| Cover story | What the audit finds |
| --- | --- |
| Say nothing | The shelf is short of what the books promise |
| Record the consumption honestly | Grain went in and no ale came out |
| Write it off as spoilage | The loss rate is not a plausible one for this region |

The only clean way through is to run a lawful operation large enough that the diversion
disappears into its ordinary variance. That is what caps contraband output as a fraction of
legitimate capacity, and it is why the brewery matters as much as the still.

Cellar space is the other ceiling: the inspector counts the warehouse, not the cellars, so
contraband beyond your hidden storage capacity has to sit somewhere he walks.

## Building it

The whole pipeline runs without a display or a monitor.

```bash
tools/install_unity.sh      # editor plus the windows-mono module
tools/run_tests.sh editmode # 39 tests, no graphics required
tools/build.sh both         # build/windows/Undertown.exe and build/linux/Undertown.x86_64
```

Unity Personal activates from the command line on Unity 6:

```bash
"$EDITOR_ROOT/Editor/Unity" -batchmode -nographics -quit \
  -username '<unity account>' -password '<password>' -logFile -
```

Unity's documentation states that command-line activation does not apply to Personal plans.
On Unity 6 the licensing client nonetheless resolves a `UnityPersonal` entitlement group
including `com.unity.editor.headless`, so no GUI login step is needed.

## Looking at it

Development happens on a machine with no screen, so the game screenshots itself from a real
player run:

```bash
build/linux/Undertown.x86_64 \
  -screen-width 1920 -screen-height 1080 \
  -autoshot artifacts/screenshots -autoshotFrames 2 -autoshotLabel demo \
  -autoshotWarmupMinutes 15200
```

`-autoshotWarmupMinutes` fast-forwards the simulation, which is how states that are hours of
real time away — such as the day-10 inspection — get documented in a run that lasts seconds.

## Architecture

The simulation layer carries no reference to `UnityEngine`. It runs on a fixed tick, a seeded
xorshift stream rather than `UnityEngine.Random`, and integer arithmetic throughout. That is
what lets the entire game logic be verified in `-batchmode` with nobody watching a screen, and
what makes a save replayable.

```
Undertown/Assets/Scripts/Core/       simulation, no UnityEngine dependency
Undertown/Assets/Scripts/Game/       rendering, HUD, input
Undertown/Assets/Scripts/Editor/     build and scene generation
Undertown/Assets/Tests/EditMode/     unit and whole-season tests
```

The scene itself is generated by `SceneSetup`, not authored by hand — on a headless machine
anything that cannot be built from a script cannot be built at all.

## Publishing

Shipping on Steam needs the account holder in person: the $100 Steam Direct fee per title,
the tax interview and its identity verification, a payout bank account, and the 30-day
mandatory wait that only begins once the fee is paid. Final QA on Windows hardware also needs
a human, since the build machine cannot run the executable it produces.
