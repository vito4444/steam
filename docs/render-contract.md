# 渲染契约（CERE-11，CERE-14 / CERE-24 更新）

这份文档说明换装渲染这一层做什么、不做什么、上限在哪。

## 1. 一条硬规矩：不做任何风格化

真实照片的纹理是这个产品唯一的真实感来源。渲染层因此**不做**：

- 描边 / 轮廓线
- 色彩量化、调色板映射、色调统一
- 扁平化、卡通阴影、手绘质感滤镜
- 任何改变衣物像素颜色的操作

渲染层**只做**下面几件几何与光影上必需的事，且都只作用于 alpha 与交界处：

| 处理 | 做什么 | 为什么 |
| --- | --- | --- |
| 贴合 | 按底图锚点与实测身体宽度决定缩放与位置 | 照片素材的像素尺寸毫无规律，只有身体尺寸能当基准 |
| 边缘羽化 | 用「模糊过的自身 alpha」再乘一次 alpha | 收掉抠图残留的硬白边，得到软过渡；实心区域纹理不动 |
| 接触阴影 | 沿轮廓的软暗环 + 向下的投影，裁进已画内容 | 「贴纸浮在上面」和「穿在身上」之间最省成本的一道分界 |
| 遮挡裁切 | 按规则表挖除、按身体遮罩裁到轮廓内（CERE-14） | 不裁的话衣服会飘在体侧、围巾会糊在脸上 |
| 不透明度补偿 | 抠图整件欠实时把自身多叠一两遍（CERE-14） | 只动 alpha 不动颜色；权宜之计，见 `occlusion-rules.md` §9 |

遮挡与贴合的完整规则表在 **`docs/occlusion-rules.md`**，那份是规范，这份只讲边界。

界面上有两个开关（舞台工具栏），出对照图不需要改代码：

- **原始叠图 / 贴合处理** —— 关掉羽化与接触阴影
- **无遮挡 / 遮挡开** —— 关掉遮挡规则与身体遮罩裁切

## 2. 贴合怎么算

代码在 `src/renderer/src/render/`：

- `metrics.ts` — 量底图轮廓。在锚点所在的行上找出包含身体中线的那段连续不透明
  像素，长度就是那一段的身体宽度。手臂在腰胯高度是独立的段，会被自动排除；
  肩线高度手臂与躯干相连，量到的正好是含肩的肩宽。
- `fit.ts` — 解每件衣物的位置与大小。CERE-24 把单一包围盒缩放拆成语义
  `scaleX` / `scaleY`：上装、外套、连衣裙用可信肩点对齐左右肩，下装用腰点定位但
  至少覆盖胯宽，围巾第一材质行留出 `0.1 × shoulderW` 的下巴间距，鞋的材质跨度
  覆盖踝线重叠区到 `foot_base`。`fit.scale` 同乘两轴，`fit.stretch_x` 只乘横轴。
  没有可信语义点时仍回落到 CERE-14 的衣长 / 宽度夹取。细节见
  `occlusion-rules.md` §7。
- `occlusion.ts` / `mask.ts` — 遮挡规则求解与身体遮罩烘焙（CERE-14）。
- `scene.ts` — 摊平成层列表，顺带算出每层的羽化半径与接触阴影强度。衣物结构层级
  从当前 `OcclusionConfig.order` 读取；−4 ~ +4 的逐件微调会被压进相邻结构层级中点
  形成的非重叠区间，不信任调用方缓存的旧槽位 z，也不允许微调颠倒槽位顺序。
  所有尺度都以肩宽为单位，换底图 / 换画布尺寸不失准。
- `canvas2d.ts` — 合成。维护一张 accum 画布记录已画内容的 alpha，接触阴影裁进
  它，所以外套的影子落在衬衫上、衬衫的影子落在身体上，而不会糊到背景上。

用户在「贴合」面板里的微调是**相对自动解**的：缩放是同时作用于 x/y 的倍数，
横向形变只作用于 x，位移的单位是肩宽。换一版底图，已存的微调不会失准。

## 3. 渲染是可替换的一层

`src/renderer/src/tryon/` 定义了 `TryOnEngine` 接口，界面只依赖这个接口：

```ts
interface TryOnEngine {
  id; name; kind: 'layered' | 'generative'; description;
  status(): { available: boolean; reason?: string };
  mount(canvas); render(input, displayScale); toDataURL(input, opts); destroy();

  // 可选：画布上的手动微调要用。给不出就返回 null，界面自动收起拖拽微调
  hitTest?(input, displayScale, x, y): Promise<string | null>;
  fitUnit?(input, displayScale): Promise<number | null>;
}
```

- `layered.ts` — 分层贴图，当前默认。
- `generative.ts` — 生成式试穿（VTON）接入点。CERE-8 结论落地后，实现
  `VtonBackend` 并调 `registerVtonBackend(impl)` 即可接管渲染，**界面与素材库
  一行都不用改**。backend 缺席时状态如实报「未接入」并回落到分层贴图。

设置页的「换装渲染引擎」就是这个开关，可用与未接入分别标注。

## 4. 上限在哪（必须如实说明）

下面这一节是给**要不要花钱走生成式试穿**这个决定用的，所以只写实测结论，
不写场面话。所有判断都来自 CERE-10 的 41 件真实素材 + CERE-6 写实模特底图，
遮挡规则全开，对比图见交付附件。

### 4.1 规则解决了什么（可以放心记在账上）

| 原来的毛病（`fig-05`） | 现在 | 靠什么 |
|---|---|---|
| 围巾贴到脸上 | 围巾停在下巴以下 | `scarf_below_chin` 守卫 + 锚点从颈点改到下巴 |
| 毛衣浮在胸口、只有巴掌大 | 覆盖肩到胯，比例正常 | 上装改按衣长驱动缩放 |
| 袖子、下摆飘在体侧 | 超出轮廓的部分被裁掉 | 身体遮罩 |
| 手提包比模特躯干还大 | 尺寸正常 | 配饰不再采信自动量出来的 landmarks |
| 一双鞋只有脚踝那么宽 | 与双脚站距匹配 | 鞋的宽度参照改成站距 |
| 连衣裙与上下装同时在身上 | 互斥自动卸下 | 互斥规则表 |
| 外套、鞋、袜的前后关系随意 | 按规则表固定 | 画序 + 成对挖除 |
| 抠图欠实的件能看见身体 | 基本不透了 | 不透明度补偿（权宜，根因在素材侧） |

也就是说：**「谁盖谁」这一类问题，分层贴图能解决得相当彻底，而且解法是可配置的
规则表，不是一堆特判。**

### 4.2 规则解决不了什么（这才是要看的部分）

一句话：**规则解决的是「谁盖谁」和可穿戴区域的几何对齐，解决不了「素材和模特
不是同一次拍摄」。** CERE-24 的双轴语义缩放可以同时对齐肩宽与衣长、鞋宽与脚底，
但不能把平铺袖子变成自然垂臂，也不能修正侧身透视、衣架造成的褶皱或不同来源的
光照方向。渲染层为保留原始颜色与纹理不会重打光，因此这些限制是明确的产品上限。

| 场景 | 现在长什么样 | 为什么调不好 |
|---|---|---|
| **摊平拍、袖子展开的上装** | 躯干比例对，但袖子被裁掉，看起来像无袖 | 素材里袖子朝两侧水平伸展，模特手臂垂在体侧。两者不是一个姿势，只能二选一：不裁就飘在空中，裁了就没袖子。**再怎么调参数也只是在这两种坏之间挑一个** |
| **挂着拍、被衣架带歪的上装** | 整件偏窄、略斜 | 包围盒被衣架和垂坠拉长，衣长与宽度两路都失真。可以手动拖回来，但自动解不出来 |
| **紧身 / 贴身款** | 边界能看出是贴上去的 | 贴身款没有宽松量可以吸收误差，肩线角度差 2° 就看得出来 |
| **复杂叠穿（3 层以上）** | 层与层之间没有互相压出的褶皱 | 分层贴图只能整层压整层。真实叠穿里外套会把里面的衣服压出形变，这是生成才能给的 |
| **两件不同来源的素材叠一起** | 光影方向打架 | 各自的高光是各自拍摄时那束光打出来的，渲染层不敢改颜色，也就没法统一 |
| **侧身 / 非正面素材** | 明显歪 | 模特是正面站姿，透视根本对不上 |
| **产品包装照、多件同框、卷成一团的配件** | 完全不能看 | 例：折叠塑封的衬衫、并排两条短裤、盘成一圈的皮带。这是素材筛选的问题（CERE-12 的质检门槛），渲染层无解 |

### 4.3 一句话结论

- **正面平铺拍的单件、宽松款、外穿件**（毛衣、夹克、连衣裙、鞋、包）：调完之后
  **能看搭配效果**，颜色和款式都是真的，判断「这两件配不配」是够用的。
- **紧身款、袖子姿势对不上的件、复杂叠穿、侧身素材**：**无论怎么调都出不了自然
  效果**。上限就在「大致像穿着」，到不了「像照片」。
- 手动微调（拖 / 缩放 / 层级 / 塞衣角）能把单件救回来，且可存档 —— 这是分层贴图
  相对生成式唯一的优势，本轮已经做实。但它是**逐件的人工成本**，衣橱越大越不划算。

所以：如果目标是「快速看颜色和款式搭不搭」，这条路线够了，且离线、零成本、即时。
如果目标是「看起来像我真的穿上了」，得换 CERE-8 那条生成式路线 —— 这就是把渲染
做成可替换一层的原因。
