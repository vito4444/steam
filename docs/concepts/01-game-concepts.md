# 方案 A｜DECODER: NIGHT WATCH（深夜监听站）

> **主推方案**

## A.1 一句话定位

冷战末期，你是边境监听站的夜班译电员。用桌上的物理设备把空中的加密信号翻译成情报，而你上报的每一个字都在改变别人的命运。

## A.2 玩家在做什么（核心循环）

一个"班次"约 12–20 分钟，玩家坐在固定工位上完成下面这条链：

**第 1 步：搜频。** 转动主频率旋钮扫过波段。绝大多数频率是噪声墙——白噪声、大气啸叫、邻台串音。有效信号出现时有三重提示：耳机里的音色变化、示波器上的波形收敛、信号强度表的抬升。玩家必须靠**听**先定位大致位置，再用微调旋钮把载波对准（对准与否会体现为音高偏移和波形抖动）。

**第 2 步：识别信号类型。** 抓到信号后判断它是哪一种：

| 类型 | 表现 | 解码手段 |
|---|---|---|
| 摩尔斯电码 | 长短蜂鸣 | 对照码表手抄，或开启自动转写辅助 |
| 数字电台 | 单调女声循环念五位数字组 | 一次性密码本逐组相减 |
| 慢扫描传真（SSTV） | 尖锐扫描啸叫 | 手动校准同步频率，让传真机逐行画出图像 |
| 倒频加密语音 | 完全听不懂的乱码人声 | 调整倒频参数，直到语音还原 |
| 遥测数据流 | 规律的数据爆发 | 判读脉冲间隔，还原数值 |

**第 3 步：解码。** 这是玩法主体，每种类型有独立的交互装置：

- **摩尔斯**：屏幕下方是一条实时滚动的音频波形。玩家用打字机敲下自己听到的字母，敲错会留下涂改痕迹（不会静默纠正）。熟练后玩家会开始不看码表直接听写——这是设计上刻意留出的成长曲线。
- **一次性密码本**：桌面右侧的密码本是逐页可翻的实体。玩家找到当日页码，把电文数字与密码本数字逐位做模 10 减法，结果查字母表。做错一位，后面全错，且游戏**不会提示**——玩家要自己发现译文不通顺然后回头查。
- **SSTV 传真**：这是最具视觉冲击的一种。传真机开始逐行吐纸，玩家实时调整同步旋钮：调偏了图像会斜切、错位、拉花；调准了才能得到清晰照片。**照片本身是剧情线索。**
- **倒频语音**：两个旋钮控制倒频轴与偏移，玩家在连续的音频空间里搜索"人话"出现的那个点。

**第 4 步：交叉验证。** 解出的内容通常不完整或有歧义。玩家转向工位左侧的档案柜——历史电报存根、边境地图、人员花名册、往期报纸。把碎片拼起来才能判断这条情报到底在说什么。

**第 5 步：上报。** 填写制式电报表格：呼号、时间、频率、内容摘要、威胁等级（例行／注意／紧急／最高优先）。签字，塞进气动管道，"啪"一声送走。

**第 6 步：承担后果。** 下一班开始前，玩家会读到三样东西：官方回电（对上报的评价）、当日报纸（外面世界发生了什么）、值班室黑板上同事留的字条（人味儿）。上报准确度和威胁等级判断会真实改变这三样东西的内容。**没有分数，只有后果。**

## A.3 进程结构

**16 个夜班**，每班一条主线信号 + 2–4 条支线／干扰信号。三幕：

- **第 1–5 班（学徒）**：只有摩尔斯和明码。教会玩家设备操作。主线是常规边境通讯。
- **第 6–11 班（怀疑）**：解锁密码本和 SSTV。玩家开始在不同频率上反复听到同一个不该存在的呼号。上级明确指示"忽略该频率"。玩家可以听话，也可以偷偷记录。
- **第 12–16 班（抉择）**：那个呼号开始直接回应玩家。玩家必须决定上报什么、隐瞒什么。**3 个主要结局 + 若干变体**，由玩家在中后段的上报记录决定，不做显式选项菜单。

**通关时长**：首周目 6–9 小时。二周目因为知道该听哪个频率会明显更快，但会解锁"你第一次错过了什么"的视角。

## A.5 美术方向

**时代与地域**：1985 年前后的东欧／苏联军用电子设备。

**具体材质清单**：
- 机箱：军绿或米灰烤漆钢板，边角磕碰露出底漆，丝网印刷的西里尔字母标签
- 旋钮：黑色贝克莱特（酚醛树脂），带滚花边缘和白色刻度线
- 指示灯：氖灯的橙红色、氙灯的惨白
- 显示：CRT 单色绿磷光，带余辉拖尾和轻微枕形失真
- 纸张：泛黄电报纸、蓝色复写纸、油印模糊的表格
- 环境：混凝土墙面、暴露的线管、结霜玻璃

**三光源布局**（这是决定画面质感的关键，也是低成本出效果的方法）：
1. **桌面台灯**：暖黄（约 2700K），锥形光斑，照亮桌面纸张，是画面的视觉中心
2. **CRT 屏幕**：磷光绿（约 520nm），从下往上打在玩家视野正前方设备上，随信号变化而闪烁
3. **窗外光**：冷蓝（约 8000K），从右侧斜入，被窗框切成条状。探照灯扫过时会短暂扫亮整个房间

**为什么这套配色成立**：暖黄／绿／冷蓝三色对比强烈，即使几何体简单、贴图分辨率不高，画面也有强烈的氛围识别度。这一点对"美术资源受限"的项目是决定性的。

**后处理**：胶片颗粒、轻微色差、CRT 扫描线（仅屏幕区域）、景深（聚焦桌面时背景虚化）。

## A.6 技术负担拆解

| 模块 | 负担 | 说明 |
|---|---|---|
| 场景几何 | **低** | 一个房间，约 40–60 个物件，其中约 25 个可交互 |
| 角色 | **无** | 不出现 3D 人物。所有人物通过声音、文字、照片存在 |
| 物理 | **极低** | 只需要纸张的简单拾取放置，不需要刚体模拟 |
| 联网 | **无** | 纯单机 |
| AI／寻路 | **无** | 无 NPC |
| **音频合成** | **高（核心）** | 见下 |
| 交互控件系统 | **中** | 旋钮、拨杆、按钮的手感需要反复打磨，这是"好玩"的来源 |
| 存档系统 | **中** | 需记录每次上报的完整内容以驱动后果系统 |
| 本地化 | **中** | 中英双语，见 A.9 |

**音频系统是本方案的技术核心**，展开说明：

- **可完全程序化生成**：白噪声、粉噪声、载波音、摩尔斯电码（点划时序精确可控）、SSTV 编码音（真实 SSTV 协议可实现，图像→音频→图像的往返可验证）、遥测脉冲、静电爆音。这部分不需要任何音频素材，代码生成，且**可以自动化测试**（解码正确性可以断言）。
- **需要录音的**：数字电台的人声报数（0–9 十个数字 + 呼号）、少量剧情语音片段、环境音（暖气管道、风声、纸张翻动）。数字电台的人声可以用 TTS 生成后叠加磁带失真、带宽限制（300–3400Hz 电话带宽）、抖晃（wow & flutter）处理，成品与真实数字电台录音在质感上很接近。**这一项需要用户确认是否接受 TTS 方案。**
- **实时 DSP**：调频搜索时的音色渐变、倒频加密／解密、频率失配导致的音高偏移。用 Unity 的 `OnAudioFilterRead` 实现，CPU 开销可控。

## A.9 本地化

**必做简体中文。** 依据：Steam 中文玩家基数大，且解谜推理品类对文本依赖度高，无中文等于放弃这块市场。

**但有一个设计冲突必须提前解决**：摩尔斯电码是拉丁字母体系，中文玩家听写摩尔斯得到的是英文字母。解决方案有三种，需要选择：

1. **译文层**：玩家听写字母得到英文原文，游戏在旁边同步给出中文译文（保留"我在破译外文情报"的真实感）
2. **中文摩尔斯**：使用真实存在的《中文电码》（四位数字对应一个汉字，这是真实的历史系统，1871 年就有了）。这个方案**在题材上更强**，因为它是真的
3. **双轨**：英文站用摩尔斯，中文站用中文电码，作为不同的信号来源

**推荐方案 2 或 3**——中文电码是一个绝大多数玩家没在游戏里见过的真实系统，本身就是卖点。

## A.10 风险与对策

| 风险 | 严重度 | 对策 |
|---|---|---|
| 摩尔斯／密码本对普通玩家门槛过高，劝退 | **高** | 前 5 班做严格的渐进教学；提供三档辅助（自动转写、码表常驻、密码本自动对齐），且辅助开关放在设置里而非成就墙上，不惩罚使用 |
| 音频驱动玩法对听障玩家不可玩 | 高 | 全部音频线索必须有视觉等价物：示波器波形、频谱瀑布图、摩尔斯的可视化点划条。这不是可选项，是发行前的硬性验收标准 |
| 数字电台人声需要配音 | 中 | 先用 TTS + 失真处理做原型验证，若质感不足再考虑真人录音 |
| 冷战题材在部分地区敏感 | 中 | 架空国名与地名，不使用真实国家名称与政治符号 |
| 谜题设计工作量被低估 | **高** | 55–70 条谜题是本项目最大的工作量。必须先做 3 条完整谜题的垂直切片验证设计流程可复制，再批量生产 |
| 固定视角被评价为"内容单薄" | 中 | 靠窗外景色变化、房间随剧情的细节增减（新增的档案、被撕掉的日历、桌上多出来的东西）制造推进感 |

# 方案 B｜DECODER: DEEP FIELD（深空信标）

## B.1 一句话定位

你是一座即将退役的射电天文台最后一名值守员。一个不属于任何已知星表的信号正在重复播送，你必须在天文台断电前把它解出来。

## B.2 与方案 A 的关系

**B 是 A 的题材变体，共用约 70% 的系统实现**：搜频、信号识别、解码、交叉验证、上报的循环完全一致。差异在三点：

1. **多出"天体力学"维度**：信号源在天球上移动。玩家要记录每次出现的时间和方位，推算它的轨道，预测下一次窗口。错过窗口就要等下一个周期（游戏内数天）。这给玩法加了一层"规划"，比 A 更硬核。
2. **解码对象是未知语言而非已知密码**：不是查密码本，而是像 Chants of Sennaar 那样从上下文归纳符号含义。
3. **氛围从"压抑监视"变成"孤独敬畏"**。

## B.4 相对方案 A 的优劣

**优势**：
- 科幻题材的国际接受度更宽，无政治敏感性，中文市场接受度也更好
- "第一次接触"的题材自带戏剧张力，Capsule 图更好做
- 天体力学层给了硬核玩家额外深度

**劣势**：
- **谜题设计难度显著更高**。冷战密码本是真实系统，玩家能理解其逻辑，解开时有"我掌握了一门技术"的成就感；外星信号缺乏现实锚点，很容易滑向"猜开发者心思"，这是解谜游戏最致命的设计失败
- Chants of Sennaar 在"归纳未知语言"这个玩法上已经做到 98% 好评、33,688 评论的水准，正面对比压力大

## B.5 定价与体量

与方案 A 相同（$17.99，6–9 小时）。天体力学层会额外增加约 15% 的系统开发量和相当多的数值调试。

# 方案 C｜DECODER: ROOM 404（纯桌面调查）

## C.1 一句话定位

一台 1999 年的电脑被人送到你手上。主人失踪了。所有答案都在这台机器里，包括那些他以为已经删掉的。

## C.2 核心循环

全屏是一套伪造的 1999 年操作系统。玩家的全部操作是：浏览文件、看照片、读邮件、听语音留言、破解密码、拨号上网访问当年的网站、在早期搜索引擎里查线索。

**核心机制是"密码递归"**：每个加密文件的密码，都藏在另一个已解开的文件里的某个细节中（一个生日、一句歌词、一张照片背面的字）。玩家的进度就是密码链的展开。中段引入一个转折——有些文件被人**故意留下**给你看。

## C.3 画面视角对标

| 对标项 | 参考游戏 | 商店页 | 本地截图 |
|---|---|---|---|
| 伪操作系统窗口界面（**主要对标**） | The Operator | [app/1771980](https://store.steampowered.com/app/1771980/) | `the_operator_0.jpg`、`the_operator_1.jpg` |
| 早期互联网检索式推理 | The Roottrees are Dead | [app/2754380](https://store.steampowered.com/app/2754380/) | `the_roottrees_are_dead_0.jpg` |
| 终端／命令行美学 | Hacknet | [app/365450](https://store.steampowered.com/app/365450/) | — |
| 线索归档与推理填空 | The Case of the Golden Idol | [app/1677770](https://store.steampowered.com/app/1677770/) | `the_case_of_the_golden_idol_0.jpg` |

**The Operator 那张截图的具体构成**（这是方案 C 要复制的界面语言）：深蓝配色，顶部任务栏显示当前任务与联系人头像和时钟；桌面左上角是文件夹图标；中央浮着三个可拖动窗口——监控视频播放器（带帧号、编解码器、分辨率等伪元数据）、绿色线框的图像分析窗、人员数据库档案（含 `ERROR 403 Access Forbidden` 权限拦截）；右侧是与外勤特工的实时聊天栏。**信息密度很高，但全部是 2D UI。**

## C.4 技术负担

**全场最低。** 没有 3D 场景、没有光照、没有音频合成。核心工作量是：一套窗口管理系统 + 一个内容数据库 + 大量美术素材（伪造的照片、扫描件、网页）。

**这个方案在本项目的开发条件下有一个独特优势**：云端虚拟环境没有 GPU，3D 场景的渲染迭代要靠软件渲染，很慢；而纯 2D UI 在软件渲染下几乎无损，截图比对可以做到像素级精确。**方案 C 是唯一能在云环境里做到"所见即最终效果"的方案。**

## C.5 风险

| 风险 | 严重度 | 说明 |
|---|---|---|
| 赛道已有强者 | **高** | Roottrees（97%，9,654 评论）、The Operator（92%，8,777）、Her Story（89%，10,384）、Obra Dinn（97%，34,940）都在这条线上，且都是精品 |
| 代码写完只完成 20% | **高** | 这类游戏的成败 100% 取决于谜题链和文本质量。系统两三周能搭好，内容要花掉全部剩余时间 |
| Capsule 难做 | **中高** | 一堆窗口界面很难做成有吸引力的头图，而调研结论明确指出 Capsule 是转化漏斗的第一道闸 |
| 美术素材需求量被低估 | 中 | 伪造的照片、扫描件、网页截图数量庞大，每一张都要有说服力 |

## C.6 定价

$14.99–$17.99。No Case Should Remain Unsolved 定价仅 $4.89 却拿到 10,485 评论，说明这个品类的低价策略也成立，但依调研结论，低于 $9.99 会压低品质预期。

## E.1 一句话定位

你在城郊开一家旧电子设备修理店。每台送修的机器里都留着上一任主人的东西——录音、照片、没发出去的信。修好它是工作，读懂它是另一回事。

# 推荐与理由

## 首选：方案 A（DECODER: NIGHT WATCH）

四条理由：

1. **它同时踩中两条被验证的信号，却不在任何一条的拥挤区**。玩法骨架取自 IRON NEST（7 天前刚被单人开发者验证，98% 好评，全球畅销榜第 25），内核取自 Obra Dinn / Roottrees / Operator 这条跨越 13 年的解谜推理谱系（好评率长期稳定在 92%–98%）。而"冷战无线电监听"这个具体题材，在本次调研抓取的全部 200+ 条榜单数据里没有出现直接竞品。

2. **它的成本结构最适合当前的开发条件**。一个房间、无人物、无联机、无物理、无 AI。美术上靠三光源配色而非资产堆量出效果。最重的音频部分恰好是**可以程序化生成并自动化验证**的——摩尔斯电码和 SSTV 都是有严格规范的真实协议，可以写单元测试断言"编码后再解码等于原文"。这在自动化自检管线里是极大的优势。

3. **它的玩法内核就是项目代号本身**。decoder 不是一个贴上去的名字，它就是玩家在做的事。

4. **中文电码是一个真实存在但几乎没被游戏用过的系统**（四位数字对应一个汉字，1871 年启用）。把它作为中文版的核心解码机制，既解决了本地化的设计冲突，又提供了一个国际版没有的独特卖点。

## 备选：方案 C（DECODER: ROOM 404）

如果对开发风险的容忍度更低，方案 C 是最保守的选择：技术负担最低、云环境迭代友好度最高、有跨 13 年的品类验证。代价是竞争更激烈、Capsule 更难做、且成败几乎完全押在内容质量上。

## 可组合

方案 A 与方案 C **共用同一套底层系统**（信号／线索数据模型、证据交叉验证、上报判定、后果系统）。若先做 A，C 可以作为后续 DLC 或第二作，复用度约 50%。反之亦然。

# 需要用户决策的问题

以下问题会实质改变架构和工作量，**必须在原型开发前确认**：

1. **选哪个方案？** 推荐 A，备选 C。
2. **中文摩尔斯方案选哪种？** 推荐"中文电码"（真实历史系统，独特卖点）。
3. **数字电台人声是否接受 TTS + 磁带失真处理？** 若要求真人配音，需要额外的录音安排。
4. **目标体量是完整商业版（6–9 小时，16 关）还是先做可发行的小体量版本（2–3 小时，6 关，定价 $9.99）？** 后者能显著提前发行时间点，但定价上限受限。
5. **是否需要先做免费 Demo？** 调研结论指出 Demo 玩家转化率显著高于仅看预告片的玩家，且 Next Fest 是最强的愿望单增长渠道。
6. **美术资源从哪来？** 当前云环境无 GPU、无美术团队。可选路径：程序化生成几何 + PBR 材质、CC0 素材库、外包、或 AI 辅助生成贴图。这一项直接决定画面上限。
