## 怎么读这份文档

五个方案是按**不同的摄像机视角**来区分的，因为视角决定了美术资产总量、性能开销和玩家的情绪距离——它是所有下游决策的源头。每个方案都独立完整，你只需要选一个。

| 编号 | 代号 | 视角 | 品类 | 核心风险 | 资产量 |
| --- | --- | --- | --- | --- | --- |
| A | ABYSSAL | 第一人称固定工位 | 硬核模拟 + 氛围恐怖 | 玩法门槛高 | 最小 |
| B | OVERCLOCK | 斜俯视可缩放 | 自动化 + roguelite | 系统深度要求极高 | 小 |
| C | NIGHT SHIFT | 第一人称自由移动 | 4 人合作恐怖 | 赛道饱和 + 联网复杂度 | 中 |
| D | SALVAGE | 第一人称零重力 | Cozy 拆解修复 | 美术调性要求高 | 中 |
| E | DEAD DROP | 第三人称越肩 | 单人撤离 roguelite | 战斗手感 + 动画量 | 最大 |

每个方案末尾都有一节「本环境可行性评估」，写的是在**当前这台没有独立显卡的 Linux 云开发机**上，这个方案能被自动化开发和自检到什么程度。这是硬约束，不是理论讨论，详见[技术可行性文档](03-tech-feasibility.md)。

# 方案 A —— ABYSSAL（深渊）

## A.1 一句话

**你是一座深海钻井平台上唯一的夜班操作员。你的工作是让钻头持续下钻，别让平台沉下去。海水外面有什么，不在你的工作职责范围内。**

## A.2 核心幻想

不是英雄，是**值班员**。玩家的成就感来自「我读懂了这台机器」，而不是「我打赢了谁」。这正是 IRON NEST 那两个人验证过的幻想——它在 2026 年 8 月直接把这款两人作品送进了 Steam 热销第 4 名。

在此之上叠加一层：**你并不完全确定外面有没有东西。** 这一层几乎不增加开发成本（舷窗外只需要粒子、体积雾和几个剪影），却能把游戏同时挂上「模拟」和「心理恐怖」两个标签——后者是 2026 年 90 天愿望单增长 +572% 的品类，是整张 Steam 需求热力图上最强的信号。

## A.3 核心循环

### 单次班次循环（一局约 25–40 分钟）

```
接班（读交接班笔记，知道上一班留下了什么烂摊子）
  ↓
启动流程（按正确顺序启动泵、发电机、冷却回路，顺序错了会跳闸）
  ↓
┌─────────────── 主循环（重复 6–12 次）───────────────┐
│  读取传感器（钻压、扭矩、泥浆密度、环空压力、井底温度）  │
│    ↓                                                │
│  在纸质图表上手工绘制趋势线（玩家真的要用鼠标画）        │
│    ↓                                                │
│  判断当前地层（砂岩 / 页岩 / 盐层 / 气囊）             │
│    ↓                                                │
│  调整参数（钻压、转速、泥浆配比、泵冲程）                │
│    ↓                                                │
│  处理突发事件（卡钻 / 泥浆漏失 / 井涌 / 设备故障）       │
└─────────────────────────────────────────────────────┘
  ↓
交班（写交接班笔记，你写的内容会成为下一局的开局条件）
```

### 关键设计：交接班笔记

这是本方案的**结构性创新**，也是差异化的核心。

玩家在下班时必须手写一张交接班笔记（在若干预设短语里点选组合，不是自由输入）。这张笔记有两个作用：

1. **下一局的开局状态由它决定。** 如果你在笔记上勾了「三号泵有异响，已降载运行」，下一局开局时三号泵就真的是降载状态。如果你没写，下一局开局它可能直接坏掉，而你不知道为什么。
2. **它会被「评估」。** 每 5 个班次后，公司会寄来一份绩效评估，逐条对比你写的内容和传感器日志的实际记录。谎报、漏报、写得含糊都会扣分。扣到一定程度会触发不同的结局分支。

这个机制的价值在于：它用极低的开发成本（一套短语库 + 一套比对逻辑）制造了**长期后果**和**道德压力**，而这正是纯模拟游戏最缺的东西。它也天然产生叙事：玩家隐瞒了故障 → 下一班出事 → 玩家开始怀疑自己 → 恐怖氛围有了着力点。

## A.4 视角与摄像机

**第一人称，站姿，半固定。**

| 参数 | 取值 | 理由 |
| --- | --- | --- |
| 摄像机高度 | 1.68 m | 站在控制台前的平均视高 |
| 视场角（垂直） | 55°（对应 16:9 下水平约 87°） | 略窄，强化幽闭感；模拟类不需要广角 |
| 移动方式 | 在约 4×6 m 的控制舱内自由行走，但所有交互点都在走两三步之内 | 保留空间感，但不做真正的探索 |
| 交互视角 | 靠近控制台时平滑过渡到「专注视角」：摄像机吸附到设备正前方，FOV 收窄到 40°，鼠标从「转头」切换为「操作旋钮/拨杆」 | 这是 IRON NEST 和 Hardspace: Shipbreaker 都在用的手法，能同时保证沉浸感和操作精度 |
| 头部摆动 | 走动时轻微（振幅 ≤2 cm），操作时完全关闭 | 操作时摆动会让精细交互变得难受 |
| 手部表现 | 有第一人称手臂，但只做「伸出去拧」和「拿起放下」两类动作 | 避免复杂的手部 IK 和抓取动画 |

**为什么是这个视角：** 摄像机永远在小房间里，意味着我们只需要制作**一个房间**的资产，而且每一个资产都会被玩家近距离长时间盯着——这是资产投入产出比最高的配置。同时第一人称是「氛围恐怖」聚类的标准视角。

## A.5 画面参考（Steam 上的具体对照）

| 参考游戏 | 参考的是什么 | 具体到画面 |
| --- | --- | --- |
| **IRON NEST: Heavy Turret Simulator** | 整体视角结构、控制台密度、纸质道具的存在感 | 玩家视野被仪表盘占满，正中间是一堆刻度盘和拨杆，右下角桌面上摊着一张纸质地图和几支彩色铅笔。视野里几乎看不到「地面」和「天花板」 |
| **Hardspace: Shipbreaker** | 工业质感、UI 与世界的融合方式、警示色的用法 | 大面积哑光金属 + 高饱和度的橙黄警示条 + 全息 UI 直接贴在物理表面上，而不是浮在屏幕上 |
| **Barotrauma**（2D，但美学参考） | 深海压抑感、故障传播的表现方式 | 昏暗的舱内光 + 舷窗外的漆黑 + 破损时的水花和火花 |
| **SOMA** | 舷窗外「有东西」的处理方式 | 大部分时间外面什么都没有；偶尔有一个巨大的剪影缓慢经过，不解释，不追击 |
| **PowerWash Simulator** | 「专注视角」的镜头过渡手感 | 靠近目标时镜头平顺贴近，操作时画面完全稳定 |

## A.6 美术方向

- **色板：** 主色为深青绿（#0F1E22）和锈橙（#B85C1E），点缀高饱和警示黄（#F2C14E）和故障红（#D93A2B）。整体明度压得很低，让屏幕上任何一个亮点都变成注意力焦点。
- **材质：** 全部走 URP 的 Lit 着色器，但只用三张贴图（Albedo / Metallic-Smoothness / Normal），分辨率上限 1024。金属表面用同一套磨损遮罩复用。
- **光照：** 全部烘焙（Baked GI）。舱内只有 4–6 个实时点光源用于闪烁的告警灯。舷窗外用一个体积雾体积 + 一个非常暗的方向光。**不用实时阴影**，除非是手电筒。
- **后处理：** Bloom（阈值高，只让告警灯发光）、Vignette、轻微色差、胶片颗粒。**不用 SSAO 和 SSR**，太贵且低多边形场景收益小。
- **UI：** 无 HUD。所有信息必须从物理仪表上读。这既是设计选择，也省掉了整套 HUD 的美术工作量。

## A.8 关键系统设计

### 钻进物理模型

不需要真实的流体仿真，用一个 5 变量的耦合方程组就够了：

```
钻速     = f(钻压, 转速, 地层硬度, 钻头磨损)
钻头磨损 = ∫(转速 × 地层研磨性 × 冷却不足系数) dt
环空压力 = g(泥浆密度, 泵冲程, 地层孔隙压力, 井深)
扭矩     = h(钻压, 地层硬度, 卡钻程度)
井涌风险 = max(0, 地层孔隙压力 - 环空压力) 的累积
```

玩家的技能就是在这个 5 维空间里找到并保持那个「安全且高效」的窄窗口。地层变化时窗口会移动，玩家必须察觉并跟上。**这套模型的全部代码量大约 400–600 行，但能产生的玩法深度远超同等代码量的任何其他设计。**

### 故障传播

设备之间有依赖图。冷却泵坏 → 钻头温度上升 → 磨损加速 → 扭矩异常 → 如果不减压就会断钻具。玩家如果只处理表面症状（看到扭矩高就减压），问题会在别处再次爆发。这套依赖图用一个有向图 + 状态机实现，可以在编辑器里可视化编辑。

### 恐怖层的克制原则

这一层必须**极度克制**，否则会毁掉模拟游戏的可信度：

- 前 3 个班次完全没有任何异常。
- 第 4 班开始，舷窗外偶尔有极暗的移动剪影，只在玩家不直视时出现（用视锥判定 + 概率触发）。
- 从不追击玩家，从不造成伤害，从不发出突然的巨响。
- 唯一的实质影响：某些设备读数会出现物理上不可能的值，而玩家必须决定要不要在交接班笔记里写出来。写了会被判定为「精神状态异常」，不写会在后续出事时被追责。

**这个设计的关键在于：恐怖的载体是「玩家自己的判断」而不是怪物。** 这既是最省成本的做法，也是「心理恐怖」聚类的定义所在（Game Oracle 原文：靠持续的不安感而非 jump scare）。

## A.9 可剪辑瞬间

- 井喷（blowout）的完整过程：警报层层升级，玩家手忙脚乱，最后要么救回来要么整个平台报废。
- 玩家在交接班笔记上撒谎，五个班次后被绩效评估当场戳穿。
- 舷窗外剪影第一次出现时的玩家反应。
- 完美班次（零故障、超额完成）的仪表全绿画面。

| --- | --- | --- |

## A.12 本环境可行性评估

| 项 | 评级 | 说明 |
| --- | --- | --- |
| 无 GPU 下的编辑器可用性 | **优** | 场景小、光照全烘焙、无实时阴影，软件渲染下可达到可交互帧率 |
| 自动化截图自检 | **优** | 场景固定，摄像机可脚本化定位，每次截图构图完全可复现，适合做视觉回归对比 |
| 自动化玩法测试 | **优** | 所有玩法都是数值状态机，可以纯 headless 跑，不需要渲染 |
| 美术资产获取难度 | 中 | 需要约 30 个高质量的机械交互件。这是本方案最主要的人工投入点 |
| 音效获取难度 | **高** | 120–180 条高质量工业音效 + 300 行配音，需要采购或委托 |

**综合：这是五个方案中最适合当前开发环境、也最贴近已验证市场的一个。**

# 方案 B —— OVERCLOCK（超频）

## B.1 一句话

**在一颗正在过热的芯片内部铺设数据流水线。热量从不下降，只会转移——你的工厂不是在生产，而是在逃跑。**

## B.2 核心幻想

自动化游戏的经典幻想是「看着我的系统自己运转」。本方案在这之上加一个**倒计时压力**和 **roguelite 的 run 结构**，解决传统工厂游戏的两个致命问题：一是新手看到 Factorio 的复杂度就跑了，二是一局要玩 80 小时，不适合小团队做内容量。

这两个品类叠加不是随便凑的：工厂/自动化是 Steam 上收入中位数最高的独立游戏品类（100+ 评测的中位数 200,000–500,000+ 美元），roguelite 紧随其后（100,000–300,000 美元）。

## B.3 核心循环

### 单次运行（一局 30–50 分钟）

```
选择芯片（4 种芯片架构，决定初始布局约束和热预算）
  ↓
┌────────────── 层循环（每局 6–9 层）──────────────┐
│  进入新的硅层，看到本层的地形（导线轨道、坏块、热点）  │
│    ↓                                            │
│  规划：把「数据源」连到「输出端口」                  │
│    ↓                                            │
│  铺设：放置逻辑门、缓冲器、总线、散热片              │
│    ↓                                            │
│  启动：数据包开始流动，热量开始累积                  │
│    ↓                                            │
│  优化：在热量击穿之前，把吞吐量提到本层的通过线以上    │
│    ↓                                            │
│  通过 → 从三个「架构升级」里选一个 → 下一层          │
└──────────────────────────────────────────────────┘
  ↓
到达内核 / 或者芯片烧毁
  ↓
用本局赚到的「蚀刻点数」永久解锁新元件（元进度）
```

### 关键设计：热量是唯一的资源

传统工厂游戏用「矿物」当资源。本方案用**热量**，而且热量的方向是反的——它只增不减，你只能**转移**它。

- 每个元件运行时产热。
- 散热片能把热量吸走，但会把它推给相邻格子。
- 热量在网格上按扩散方程传播。
- 某个格子超过阈值 → 该格子的元件永久烧毁 → 你的流水线断了 → 你必须在运行中改线。

**这一条规则同时解决了三个设计问题：** 它给了空间布局以真实意义（不能把东西堆一起）、它给了时间压力（不能慢慢想）、它让每一局都必然走向失败（roguelite 的 run 需要有终点）。

## B.4 视角与摄像机

**斜俯视，可自由缩放和旋转的第三人称观察视角（没有可控角色）。**

| 参数 | 取值 | 理由 |
| --- | --- | --- |
| 投影 | 透视，FOV 35°（偏窄，接近正交但保留深度感） | 窄 FOV 让网格边缘不变形，方便精确放置 |
| 俯角 | 默认 42°，可在 20°–75° 之间拖动调整 | 42° 能同时看清平面布局和元件的立体轮廓 |
| 摄像机距离 | 默认 22 m，可缩放到 6 m（看单个元件细节）到 60 m（看整层全貌） | |
| 旋转 | 绕垂直轴自由旋转，或按 45° 步进吸附 | 步进吸附对网格类游戏更友好 |
| 移动 | WASD 平移 + 边缘推移 + 中键拖拽 | 标准 RTS 操作 |
| 特写模式 | 双击元件 → 摄像机飞到该元件旁边，FOV 收到 25°，可以看到数据包实际穿过它 | 这是本方案唯一需要「好看」的镜头，用来做宣传素材 |

**为什么是这个视角：** 自动化游戏的核心快感是「俯瞰自己造的系统在运转」，必须能一眼看到全局。同时可缩放到特写，让玩家能欣赏细节——这是 Satisfactory 相对 Factorio 的最大优势，也是它能卖得更贵的原因。

## B.6 美术方向

**这个方案的美术方向是「几乎不需要传统美术」，这是它最大的技术优势。**

- **几何：** 所有元件都由基础几何体（立方体、圆柱、棱柱）组合而成，全部程序化生成或用极少量手工模型。单个元件不超过 300 个三角面。
- **材质：** 只有两种材质——「暗基底」（纯黑，粗糙度 0.9）和「发光线」（Unlit + Emission）。**没有贴图，没有 UV 展开，没有法线贴图。**
- **颜色即信息：** 青色 = 数据流，橙色 = 热量，紫色 = 高优先级数据，红色 = 过热警告，白色 = 玩家当前选中。玩家一眼扫过去就能读懂整个系统状态。
- **光照：** 完全不用实时光照。全部靠 Emission + Bloom。这意味着**渲染开销极低，在软件渲染下也能跑到可用帧率**。
- **动效是本方案的主要「美术」投入：** 数据包的流动、热量的扩散涟漪、元件烧毁的瞬间、升级选择时的界面动画。这些全部是着色器和粒子，可以用代码写。

## B.8 关键系统设计

### 热扩散

用二维网格上的显式差分：

```
T[x,y] 下一帧 = T[x,y] + Δt × ( α × (相邻四格温度和 - 4×T[x,y]) + 本格产热 - 散热 )
```

网格规模控制在 64×64 以内，每帧更新一次，用 Unity 的 Job System + Burst 编译，完全不需要 GPU。**这个系统在纯 CPU 上跑，意味着它在当前无显卡的开发环境里可以完整测试。**

### 数据包流动

不做逐个包的物理仿真（太贵），而是用「流量图」：每条边有吞吐量上限，用最大流算法每 0.5 秒重算一次，视觉上的数据包只是按流量密度生成的粒子。**视觉表现和实际计算解耦**，这是自动化游戏能做大规模的关键技巧。

### roguelite 的构筑深度

60–80 个架构升级需要能互相组合出「构筑」。设计几条明确的构筑轴线：

- **超导流：** 极致降低发热，但吞吐量上限低。
- **暴力流：** 无视发热，靠散热片和快速重建硬撑。
- **压缩流：** 把多个数据包合并，减少总流量但增加单点负载。
- **并行流：** 大量低效但分散的线路。

每条轴线有 15–20 个协同的升级，玩家在选择时能感觉到「我这局在往哪个方向走」。

# 方案 C —— NIGHT SHIFT（夜班）

## C.1 一句话

**四个人，一座断电的数据中心，一份「重启所有服务器」的工单。工单没写的是，上一批夜班的人去哪了。**

## C.2 核心幻想

**和朋友一起在黑暗里犯蠢然后一起死。** Lethal Company、Content Warning、REPO 卖的都是这个。它的传播机制是结构性的：近距离语音 + 物理系统 + 不可预测的威胁 = 每一局都自动生成可剪辑素材，创作者变成免费的买量渠道。

数据支撑：REPO 上线后一度收入超过《文明 7》，近 2,000 条评测拿到「Overwhelmingly Positive」；Lethal Company 历史峰值同时在线 240,817 人。

**但必须同时看到衰减数据：Lethal Company 当前同时在线约 3,946 人，比峰值低约 98%。** 而且 PC Gamer 直言「『Lethal Company 克隆』已是 Steam 上仅剩的三大品类之一」。这个赛道的爆发力最强，饱和度也最高。

## C.3 核心循环

### 单次任务（一局 15–25 分钟）

```
在货车上选择本次任务（楼层、工单内容、危险等级、报酬）
  ↓
┌──────────── 楼层循环 ────────────┐
│  进入楼层（程序化生成的机房布局）    │
│    ↓                             │
│  分头找目标（服务器机柜、配电箱、备份磁带）│
│    ↓                             │
│  执行需要两人以上配合的操作          │
│    ↓                             │
│  威胁出现 → 逃 / 藏 / 断电引开      │
│    ↓                             │
│  在电力耗尽前回到电梯               │
└──────────────────────────────────┘
  ↓
结算（完成的工单 = 钱；死掉的队友 = 扣钱）
  ↓
用钱买装备 → 下一次任务的难度更高
```

### 关键设计：所有关键操作都需要两个人

这是本方案对 Lethal Company 公式的**核心改动**，用来解决它的结构性问题（玩家摸熟后恐怖退化成喜剧）。

- 重启一个机柜需要：一个人在配电室按住断路器，另一个人在机房插上跳线。两人相距 40 米以上，只能靠无线电通话。
- 无线电是**有限带宽**的：同一时刻只有一个人能说话。想说话就要按住按键，而按住按键的时候你的手电筒会熄灭。
- 威胁会**模仿队友的声音**。你听到的「左边安全」可能不是你队友说的。

**这三条组合起来产生的是「持续的社交不信任」，而这个不会随着玩家熟练度提升而消失。** 玩家越熟练，就越知道该怀疑什么，恐怖反而在加深。这是对 Lethal Company 天花板问题的直接回应——《The Mound: Omen of Cthulhu》用「理智系统」来解决同一个问题，我们用「通信信任」来解决。

## C.4 视角与摄像机

**第一人称，自由移动，低保真。**

| 参数 | 取值 | 理由 |
| --- | --- | --- |
| 摄像机高度 | 1.70 m（站）/ 0.95 m（蹲） | |
| 视场角（垂直） | 60°（水平约 91°） | 合作恐怖需要稍宽的视野，否则玩家太容易晕 |

| 头部摆动 | 明显（振幅 5–7 cm），跑动时加剧 | 制造慌乱感，也是喜剧效果的来源 |
| 手电筒 | 唯一的实时阴影光源，聚光角 35°，随呼吸轻微晃动 | |

# 方案 D —— SALVAGE（打捞）

## D.1 一句话

**在零重力的报废飞船里，把还能用的东西拆下来、修好、卖掉。没有敌人，没有时限，只有你、工具，和一船的破铜烂铁。**

## D.2 核心幻想

**秩序感。** 把一团混乱变成整齐的、分类好的、能用的东西。这是 PowerWash Simulator 和 ReStory 卖的东西，也是「cozy」标签的本质。

ReStory: Chill Electronics Repairs 在 2026 年 8 月直接进了 Steam 热销第 5 名，由 tinyBuild 发行。它的结构是：第一人称固定工位 + 深度物品交互 + 轻叙事分支。本方案把这个结构搬到零重力太空环境里，保留其低成本优势，同时用「零重力自由移动」制造视觉差异化。

## D.3 核心循环

### 单次合同（一局 20–45 分钟）

```
接合同（客户要什么零件，出多少钱，船况如何）
  ↓
飞到残骸旁，进入船体
  ↓
┌────────────── 拆解循环 ──────────────┐
│  勘察（找到目标部件，判断固定方式）        │
│    ↓                                  │
│  断电（切错线路会导致部件损坏或起火）       │
│    ↓                                  │
│  拆卸（螺栓 / 焊点 / 卡扣 / 液压锁，各有工具）│
│    ↓                                  │
│  搬运（零重力下推动大质量物体需要预判惯性）   │
│    ↓                                  │
│  归类（放进对应的收纳格，错放会被扣钱）       │
└───────────────────────────────────────┘
  ↓
回到工作台，把损坏的部件修好（值更多钱）
  ↓
结算 → 买更好的工具 → 接更难的合同
```

### 关键设计：修复比拆解值钱得多

单纯拆下来的部件按废品价卖。**修好的部件按整备价卖，差价通常是 5–10 倍。** 这把游戏的重心从「拆」转移到「修」，而「修」是一个可以做得非常有深度的工位玩法：

- 打开外壳（要按正确顺序拧螺丝，否则外壳变形）
- 诊断（用万用表逐点测量，找出坏掉的元件）
- 更换（从库存里找对应型号，型号不对会有兼容性代价）
- 校准（调节电位器，看示波器波形，调到规格窗口内）
- 测试（通电，观察，如果冒烟就白干了）

这套流程和 IRON NEST 的操作深度是同一个量级的，但情绪是完全相反的——那个是紧张，这个是放松。

# 方案 E —— DEAD DROP（死信）

## E.1 一句话

**带着能带走的东西活着离开。每一次出击都是一局独立的 roguelite，但你死掉时丢掉的装备，会出现在下一局的地图上。**

## E.2 核心幻想

**贪婪与风险的博弈。** 撤离玩法（extraction）的核心张力是：你已经拿到了足够的东西，但再往前走一点可能拿到更好的，而死了就全没了。Mistfall Hunter 在 2026 年 7–8 月连续两周进入 Steam 付费榜前十，证明这个张力现在依然有效。

本方案的改动是：**做成单人 roguelite，而不是多人撤离射击。** 这砍掉了联网、反作弊、服务器成本这三座大山，同时保留了核心张力。代价是失去了「其他玩家」这个最大的不确定性来源——所以我们用「你自己上一局的尸体」来替代它。

## E.3 核心循环

```
在据点选择装备（带进去的东西，死了就没了）
  ↓
选择目标区域（风险等级 vs 战利品品质）
  ↓
┌────────────── 出击循环 ──────────────┐
│  空降进入程序化生成的区域               │
│    ↓                                  │
│  搜刮（背包空间有限，必须取舍）           │
│    ↓                                  │
│  规避或对抗（战斗永远是亏本买卖）          │
│    ↓                                  │
│  遇到「上一局的自己」的尸体 → 可以取回装备  │
│    ↓                                  │
│  决策点：撤离 or 再深入一层              │
└───────────────────────────────────────┘
  ↓
撤离成功 → 战利品入库 / 死亡 → 装备留在原地，标记为「死信点」
  ↓
用战利品升级据点 → 解锁更好的起始装备
```

### 关键设计：死信点

玩家死亡的位置会在下一局的地图上生成一个「死信点」，里面装着上一局带的所有东西。这个点在地图上是可见的，但通常位于高风险区域（因为你就是在那儿死的）。

**这个机制把「失败」转化成了「下一局的目标」，同时保留了失败的痛感。** 它还产生了一个有趣的决策：要不要为了取回旧装备而去一个你已知很危险的地方。

# 推荐

## 首选：方案 B（OVERCLOCK）

理由按重要性排序：

1. **它是唯一一个在当前开发条件下能把「自动化开发 + 自检优化」这套流程跑到 100% 的方案。** 整个游戏的玩法是一个可以在纯 CPU 上 headless 运行的确定性模拟，这意味着可以让程序自己跑上万局做平衡性调优，而不是靠人工试玩。它的渲染是 Unlit + Emission，在软件渲染下画面和真机上的画面**几乎完全一致**，这让「截图对比目标」这条自检链路真正可信。

2. **它命中了 Steam 上收入中位数最高的两个独立品类。** 工厂/自动化（200,000–500,000+ 美元）叠加 roguelite（100,000–300,000 美元）。

3. **美术成本接近于零。** 40 个几何体模型、0 张贴图、0 行配音。这把项目的失败模式从「美术做不出来」压缩到了「设计不够深」——后者是可以通过大量迭代解决的，而前者不能。

4. **差异化清晰。** 「3D + 热力学作为唯一资源 + roguelite run 结构」这个组合，目前 Steam 上没有直接对标物。

**它的唯一致命风险是系统深度。** 因此如果选它，第一个里程碑必须是**纯文本的玩法原型**（不做任何美术），用来验证解空间是否足够大、构筑轴线是否成立。这个原型如果验证失败，可以立刻止损换方案，损失极小。

## 次选：方案 A（ABYSSAL）

如果你更看重「有已验证的市场对标物」而不是「技术上最优」，选 A。IRON NEST 用两个人的团队在 2026 年 8 月做到了 Steam 热销第 4，这是一个非常硬的市场信号。A 的技术条件同样优秀（场景固定、光照烘焙、可脚本化截图），主要额外成本是音效和配音。

## 不推荐在当前条件下选的：C 和 E

- **C（NIGHT SHIFT）** 的问题不是设计，而是**当前云开发环境无法对多人联机做有效的自动化测试**。选它等于放弃「边运行边自检」这条主线，改为高度依赖人工联机测试。加上赛道已被 PC Gamer 形容为「Steam 仅剩的三大品类之一」，风险回报比不划算。
- **E（DEAD DROP）** 的问题是射击手感和 60–80 个角色动画。**手感这个东西无法被自动化验证**，只能靠人反复试；动画无法被程序生成，只能采购或委托。这两项都不是当前条件的强项。

# 需要你拍板的问题

在开工之前，有五件事必须由你决定，因为它们会实质改变架构和交付物：

## 1. 选哪个方案？

推荐 B，次选 A。如果你想要「两条腿走路」，可以先做 B 的纯文本原型验证系统深度，同时并行做 A 的控制舱场景搭建——这两件事互不冲突，但会摊薄进度。

## 2. 交付目标是哪一档？

- **档位一：可玩的垂直切片（Vertical Slice）** —— 一个能完整体验核心循环的 Windows 构建，15–30 分钟内容，用于验证玩法和录制宣传素材。
- **档位二：Steam Demo** —— 在档位一基础上加完整的菜单、设置、存档、本地化，达到可以公开发布 Demo 的质量。
- **档位三：Early Access 首发版** —— 完整核心内容 + 至少 6–10 小时的可玩内容。
- **档位四：正式版**

**这四档的工作量是数量级递增的关系。** 我建议先明确到档位一或档位二，做完看到实物后再决定要不要继续。

## 3. 美术资产的来源？

- 全部程序化生成 / 几何体拼装（方案 B 可行，其他方案不完全可行）
- 采购 Unity Asset Store 素材（需要预算，且要注意 Steam 发行的授权条款）
- 委托外包（需要预算和时间）
- 我用代码 + 程序化建模生成（质量上限有限，但零成本）

**这个决定会直接影响方案的可选范围。** 如果答案是「零预算」，那实际上只有方案 B 可行。

## 4. 音效和配音怎么办？

方案 A 需要 120–180 条工业音效 + 约 300 行配音。方案 B 几乎不需要（电子音可以程序合成）。如果没有音效预算，这又是一条指向方案 B 的理由。

## 5. Steam 账号和发行主体准备好了吗？

Steam Direct 需要：100 美元/款、身份和税务验证、30 天强制等待期、14 天 Coming Soon 页面。**这些我无法代你完成，需要你本人操作。** 但我可以：准备好商店页面的全部素材（截图、GIF、宣传语、标签、系统需求）、配置好 SteamPipe 上传脚本、写好 Steamworks SDK 的集成代码。

**建议现在就开始走 Steam Direct 的流程**，因为 30 天强制等待期是纯粹的日历时间，和开发进度无关，越早启动越好。

# 关于概念图

`concept-art/` 目录下有为每个方案生成的概念图，用于直观对比视角和美术方向。概念图是**风格和构图的示意**，不是最终画面的承诺——实际游戏画面会受资产制作能力的限制，两者之间的差距会在后续的「成果图对比」中持续追踪和修正。
