## 一、关键路径与不可压缩的时间

Steam 发行有几段**纯日历时间**，和开发进度完全无关，只能靠提前启动来吸收。

```
支付 Steam Direct 费用
   │
   │  ← 强制等待 30 天（无法加速，无法申请豁免）
   │
   ├─ 期间可以并行做：填写商店页 → 提交商店页审核（3–5 工作日）
   │                        ↓
   │                  商店页通过 → Coming Soon 页面公开
   │                        │
   │                        │  ← 至少公开 14 天
   │                        │
   └────────────────────────┴─→ 提交构建审核（3–5 工作日，必须在商店页通过之后）
                                        ↓
                                   手动点击 Release App
```

（依据：Steamworks 官方 Onboarding 文档、Steam Direct 页面、Immutable 与 The Game Marketer 的 2026 年指南）

**结论：从付钱到能发售，最快也要约 30 天，而且这 30 天里必须完成商店页面的全部素材。**

**行动建议：现在就启动 Steam Direct 流程。** 30 天等待期和 14 天 Coming Soon 期可以完全被开发时间吸收掉，早一天启动就早一天开始积累愿望单。愿望单积累周期是发行成败的最大变量——数据显示，愿望单转化率最高的那批游戏，Coming Soon 页面平均在发售前 214 天就已挂出。

## 二、需要你本人完成的事项

以下事项涉及身份、银行账户和法律主体，我无法代办：

| 事项 | 说明 |
| --- | --- |
| 注册 Steamworks 账号 | 需要一个 Steam 账号作为基础 |
| 签署数字文件 | NDA、Steam 分发协议 |
| 身份验证 | 个人或公司的合法身份证明 |
| 税务信息 | 中国大陆开发者需要填写 W-8BEN 表（个人）或 W-8BEN-E（公司），确认税收协定待遇。耗时 2–7 个工作日 |
| 银行账户 | 用于接收收入。需要能接收美元电汇的账户 |
| 支付 100 美元 Direct 费用 | **不能用 Steam 钱包余额支付**，需要信用卡或其他支持的支付方式 |
| 最终点击 Release App | 只有账号所有者能操作 |

### 关于中国大陆开发者的额外注意事项

- 税务表格填写错误会导致 30% 的预扣税（中美税收协定下正确填写通常可以降低）。这一项建议咨询专业人士，填错的追溯修改很麻烦。
- 收款账户需要能接收美元跨境汇款。
- 如果以公司主体发行，需要营业执照等文件。以个人身份发行也是允许的。

**这些是流程性事实的陈述，不构成税务或法律建议。**

## 四、Steam 技术接入清单

### 必须做的

| 项 | 说明 | 工作量 |
| --- | --- | --- |
| Steamworks SDK 接入 | 用 Steamworks.NET 或 Facepunch.Steamworks | 小 |
| `steam_appid.txt` | 开发期必需 | 极小 |
| 正确处理 Steam 未运行的情况 | 游戏在没有 Steam 的环境下也不能崩溃 | 小 |
| 退出时正确关闭 Steam API | 避免 Steam 客户端残留进程 | 极小 |

### 强烈建议做的

| 项 | 为什么 |
| --- | --- |
| **成就系统** | 直接影响玩家参与度和评论意愿。成就的完成率数据也是宝贵的玩法反馈 |
| **Steam 云存档** | 玩家期待的基本功能，缺失会招致差评 |
| **Steam Input** | 手柄支持。也是 Steam Deck 兼容性认证的前提 |
| **Steam 统计（Stats）** | 后台能看到玩家的真实行为数据，是发售后调优的唯一数据源 |
| **富存在（Rich Presence）** | 在好友列表显示玩家正在做什么，有轻微的社交传播效果 |

### Steam Deck 兼容性

Steam Deck 的用户基数已经足够大，值得单独考虑。要拿到「Verified」标记需要：

- 默认图形设置下能达到可玩帧率
- 全部文本在 1280×800 分辨率下可读（这一条最容易踩坑，UI 字号要够大）
- 完整的手柄支持，不需要键鼠
- 启动时不弹出任何需要键鼠的对话框
- 不依赖需要外部登录的服务

**方案 B（OVERCLOCK）的渲染开销极低，是最容易拿到 Verified 的。** 方案 E（DEAD DROP）的体积雾和动态光照在 Deck 上需要专门优化。

## 五、商店页面的关键决策

### 标签（Tags）

Steam 的标签直接决定了游戏会被推荐给谁。前三个标签权重最高。建议策略：

- **第 1 个标签：** 最精确描述玩法的品类标签（不是最热门的，是最准的）
- **第 2 个标签：** 一个流量大的相关品类标签
- **第 3 个标签：** 一个能吸引特定小众受众的标签

反面例子：给一个硬核模拟游戏打「Action」标签，会把游戏推给期待动作游戏的玩家，带来的是差评而不是销量。

### 简介（Short Description）

这段文字出现在商店页顶部和所有推荐位，是转化率影响最大的一段文字。要求：

- 300 字符以内
- 第一句话就说清楚玩家要做什么
- 不用形容词堆砌（「震撼的」「史诗般的」这类词会降低可信度）
- 说清楚这个游戏和它最像的那个游戏的区别在哪

### 首图（Capsule）

Steam 用户在推荐列表里首先看到的就是这张图。它的点击率直接决定流量。原则：

- 在 231×87 的小尺寸下仍然能看清主体（大多数曝光位是小尺寸）
- 高对比度，避免暗调（暗调图在列表里会被忽略）
- 不要在图上放大段文字，只放游戏名

## 七、发售后的第一个月

发售首月通常占第一年收入的 30–50%，首周占 15–25%。这段时间的操作直接决定长期收入。

| 时间点 | 动作 |
| --- | --- |
| 发售当天 | 全天候监控崩溃报告和 Steam 论坛，任何影响启动的问题在 24 小时内修 |
| 前 3 天 | 每天至少一次热修补丁，让玩家看到开发者在盯着 |
| 前 7 天 | 回复所有的负面评测（态度决定后续评价走向） |
| 第 1–2 周 | 根据 Steam 统计数据找出玩家流失点 |
| 第 2–4 周 | 发布第一个内容更新，重新激活曝光 |
| 首月结束 | 复盘：愿望单转化率、退款率、评测分数、游玩时长分布 |

### 退款率是一个必须盯的指标

Steam 的退款政策是「2 小时内、14 天内可无理由退款」。退款率超过 15% 说明商店页面的预期管理出了问题（玩家买到的和以为买到的不一样）。这个数字在 Steamworks 后台可以看到。

## 八、待你确认的事项

1. **是否现在就启动 Steam Direct 流程？** 我的建议是「是」，因为 30 天等待期是纯粹的浪费时间，越早启动越好，且 100 美元在游戏收入达到 1000 美元后会返还。
2. **发行主体是个人还是公司？** 这会影响税务表格和收款方式。
3. **是否考虑 Early Access？** Early Access 能提前拿到收入和真实反馈，但会消耗掉「新游戏」的曝光窗口，而且发售后必须持续更新。对方案 B（roguelite，内容可持续增加）比较合适，对方案 A（有明确结局的叙事型模拟）不合适。
4. **首发是否只做 Windows？** 我的建议是「是」。Linux 构建我们内部会做（用于自动化测试），但对外发行 Linux 版本意味着要承担额外的支持成本，而 Linux 玩家可以通过 Proton 运行 Windows 版本。macOS 需要单独的构建模块和代码签名，成本更高。
5. **是否需要发行商？** 独立发行保留 100% 收入（扣除 Steam 的 30%），但要自己做全部营销。ReStory 有 tinyBuild 发行，IRON NEST 是自己发行的——两条路都走得通。如果考虑发行商，需要在有可玩 Demo 之后再接洽。
