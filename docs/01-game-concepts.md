# 方案 A：《Hunter: 金雾猎场》（代号 Aurum Mist）

> 推荐指数：★★★★★（主推）

## A.1 一句话定位

黑暗奇幻的**单人/小队 PvE 搜打撤**动作 RPG：带着可能永久失去的装备进入金雾笼罩的遗迹，与同样在搜刮的 AI 猎金人竞速抢夺，在雾中主宰追上你之前摇铃撤离。

## A.2 核心玩法循环

**局内（单局 15–20 分钟）**

```
选职业与携带装备（带进去的会掉，掂量清楚）
        ↓
空投进入程序化拼装的雾区（能见度 25–35 米）
        ↓
┌─→ 搜刮：箱子、尸体、隐藏点位，物品有品质与重量
│       ↓
│   遭遇：普通怪 / 精英怪（掉金装）/ 其他 AI 猎金人小队
│       ↓
│   决策：打？绕？跟在别人后面捡漏？
│       ↓
└── 计时推进：第 12 分钟「雾中主宰」出现，不可击杀，持续追踪玩家
        ↓
撤离：找到铃钟 → 摇铃（有声音，会引来一切）→ 传送门开启 15 秒 → 进门
        ↓
成功 = 战利品入库；死亡 = 身上所有东西留在原地
```

**局外（营地）**

```
入库战利品 → 修复世界树（主线进度）
           → 升级营地设施（锻造台、炼金台、储物柜扩容、地图情报商）
           → 解锁新职业 / 新技能树节点 / 新雾区
           → 接取委托（定向目标，提高单局收益）
```

**这个循环为什么成立**：搜打撤的核心快感来自「已经赚了很多，还要不要再贪一个箱子」的赌博感。这个感觉完全由**死亡掉落**和**撤离窗口**两个机制制造，与是否有真人对手无关。竞品《雾影猎人》靠真人 PvP 提供不确定性，代价是必须自建服务器且优化拉胯（详见调研报告 3.1 的差评清单）。我们用**行为可信的 AI 猎金人**替代：它们有自己的搜刮路线、会抢在你之前开箱、会因为听到你摇铃而赶来伏击、会在血量低时带着战利品逃向撤离点。玩家杀掉一个满载的 AI 猎金人，能拿到它身上全部东西——这正是 PvP 的核心奖励结构，但零服务器成本、零延迟、零外挂。

## A.3 视角与画面

**相机设置（具体参数，可直接落地）**

| 参数 | 数值 | 理由 |
| --- | --- | --- |
| 视角类型 | 第三人称越肩（over-the-shoulder） | 与《雾影猎人》一致，是近战搜打撤已验证的最优视角 |
| 相机距离 | 角色后方 2.8 米 | 近到能看清装备细节，远到能看到侧面来敌 |
| 相机高度 | 角色胸口上方 0.4 米 | |
| 肩部偏移 | 右偏 0.55 米 | 让角色不挡住准心区域 |
| FOV | 60°（默认）/ 55°（瞄准时）/ 68°（冲刺时） | 冲刺扩 FOV 制造速度感 |
| 碰撞处理 | 相机弹簧臂，遇墙自动拉近至最小 0.9 米 | 窄走廊必需 |
| 锁定 | **可切换软锁定**（默认开启） | 直接修掉竞品最大差评点，见下 |

**关于锁定系统——这是我们相对竞品的明确改进点。**《雾影猎人》完全取消锁定，玩家原文差评是「明明看着已经砍下去，但判定和反馈总是慢一秒」。我们的方案：默认提供**软锁定**（攻击时角色朝向自动微调向准心附近的最近敌人，修正角度上限 25°），保留玩家的瞄准责任但消除「明明打中却判定没中」的挫败感；同时在设置里提供「硬核模式：关闭软锁定」满足硬核玩家。

**Steam 画面参考（去 Steam 看这几款的截图/预告，就是我们要的画面感）**

| 参考作品 | 参考什么 |
| --- | --- |
| **雾影猎人 (Mistfall Hunter)** | 越肩机位、近战交战距离、黑暗奇幻的场景层次堆叠 |
| **Dark and Darker** | 地牢照明逻辑：手持光源是唯一可靠光源，黑暗本身是敌人 |
| **Hunt: Showdown** | 雾气与体积光的氛围密度、声音定位的战术价值 |
| **Grain Rot** | 局内 run 与局外基地建造的界面组织方式 |
| **Deep Rock Galactic: Rogue Core** | 不可击杀追猎者带来的计时压迫感、黑暗中的高对比色彩指引 |

**画面构成的具体设计（也是我们的省成本方案）**

金雾同时是世界观设定、玩法机制和渲染预算控制器：

- 能见度限制在 25–35 米 → 远景不需要制作，指数雾直接吞掉
- 场景照明以**手持提灯 + 少量点光源**为主 → 不需要复杂的全局光照烘焙
- 雾中出现的敌人先是**剪影**再是实体 → 敌人模型在中远距离不需要高细节
- 战利品与可交互物用**发光边缘（rim light）**标记 → 在低能见度里依然清晰可读，同时形成强烈的视觉记忆点

这套方案的价值在于：它让「无 GPU 环境开发」「无美术团队」「风格统一」三个约束同时得到解决，而且产出的画面在 Steam 商店页上是**有辨识度的**，不是妥协感。

## A.4 世界观与美术方向

**设定**：诸神陨落之后，神血化作金雾侵蚀大地。金雾吞噬灵魂，但雾中沉淀的「流金」是重建世界的唯一材料。你是猎金人，受女巫指引进入雾区取金。取得越多，被雾侵蚀得越深。

**美术风格**：风格化写实（stylized realism）低多边形。

- 角色面数控制在 3,000–6,000 三角面
- 材质用**三色渐变 + 强边缘光**，不依赖高精度贴图
- 色彩策略：环境去饱和（灰蓝、暗绿、黑），金色只出现在战利品和雾核上 → 玩家的注意力自动被引导到有价值的东西上
- 场景由**模块化预制件**程序化拼装（房间、走廊、庭院、塔楼），保证风格 100% 统一

## A.5 Steam 定位

| 项 | 内容 |
| --- | --- |
| 主标签 | Extraction Shooter（106 款竞品 / 中位收入 $33K / 中位评论 672） |
| 副标签 | Dungeon Crawler, Dark Fantasy, Looter, PvE, Souls-like, Procedural Generation, Co-op |
| 建议价格 | 抢先体验 $12.99 → 正式版 $16.99 |
| 发行策略 | 先发免费 Demo 参加 Steam 新品节 → 抢先体验 → 按赛季更新内容 |
| 目标受众 | 想玩搜打撤但受不了被真人虐、受不了外挂和延迟的玩家；Dark and Darker 与 Hunt: Showdown 的外围人群 |

**定位话术（商店页首句草案）**：「搜打撤的全部紧张感，没有一个真人对手。」

## A.6 内容体量与系统清单

**首个可玩版本（垂直切片）**
- 1 张雾区地图（模块化，约 12 个房间预制件的程序化组合）
- 2 个职业（近战：佣兵 / 远程：黑箭）
- 8 种敌人（4 普通 + 2 精英 + 1 AI 猎金人 + 1 雾中主宰）
- 30 件装备，4 个品质档
- 完整的搜刮-撤离-入库-升级循环

**抢先体验首发版本**
- 3 张雾区地图
- 4 个职业，每职业 2 套武器模组
- 25 种敌人
- 装备 150+，词缀系统
- 营地 6 项设施可升级
- 主线委托 20 个 + 随机委托池

## A.7 技术实现路径

| 模块 | 方案 |
| --- | --- |
| 渲染管线 | URP（Universal Render Pipeline），Forward+ |
| 关卡生成 | 自研模块化房间图生成器，基于房间连接口（socket）匹配 |
| 敌人 AI | 行为树 + Unity NavMesh；AI 猎金人使用与玩家相同的装备与背包系统 |
| 战斗 | 动画驱动的攻击判定（animation event 开关 hitbox），软锁定通过朝向插值实现 |
| 存档 | JSON 序列化 + 校验和；局内进度不存盘（这是搜打撤的赌注来源） |
| 联机（可选，二期） | Steam Networking Sockets（P2P + Steam 中继，免费），主机权威 |
| 音频 | FMOD 或 Unity 内置 + 程序化音效；雾中的方位音效是核心玩法信息 |

## A.8 当前开发条件下的可行性评估

| 维度 | 评分 | 说明 |
| --- | --- | --- |
| 美术资产可程序化产出 | ★★★★★ | 模块化建筑 + 雾遮挡，是所有方案里最省美术的 3D 方案 |
| 无 GPU 环境可开发性 | ★★★★☆ | URP + 低能见度，软件渲染下可在无头环境出图验证 |
| 玩法系统复杂度 | ★★★☆☆ | 背包、词缀、掉落、AI 搜刮行为都是纯逻辑，AI 开发擅长 |
| 战斗手感风险 | ★★★☆☆ | 近战手感需要反复调，但软锁定 + 明确的命中反馈可控 |
| 单人可完整体验 | ★★★★★ | 不依赖联机 |
| 商业天花板 | ★★★★★ | 窄标签 + 高参与度 + EA 长线，是五个方案里最高的 |

## A.9 风险与对策

| 风险 | 对策 |
| --- | --- |
| AI 猎金人行为不可信，玩家觉得「假」 | 让 AI 使用**完全相同**的规则：同样的背包容量、同样的装备、同样会怕死。它们的搜刮路线用与玩家一致的寻路和收益评估函数生成，而不是脚本巡逻 |
| 近战判定手感差（竞品最大差评） | 软锁定 + 命中停顿（hitstop 60–90ms）+ 三层命中反馈（音效、屏幕震动、受击闪白）；每次改动后做手感回归测试 |
| 程序化地图重复感强 | 每张图有 2–3 个手工制作的**地标房间**（boss 房、宝库、铃钟塔），程序化部分只负责连接。这是 Hades 与 DRG 都在用的做法 |
| 内容量在 EA 首发不足 | EA 明确标注内容范围与更新路线图，价格定在 $12.99 而不是 $19.99 |

# 方案 B：《Hunter: 巨兽契约》（代号 Beast Contract）

> 推荐指数：★★★★☆

## B.1 一句话定位

1–4 人协作的**第一人称近战巨兽狩猎**：追踪痕迹找到目标，通过破坏部位削弱它，剥取素材锻造更强的装备，再去打更凶的东西。

## B.2 核心玩法循环

```
在猎人营地接契约（目标、地形、天气、时限）
        ↓
进入程序化生成的狩猎场（森林 / 冻原 / 沼泽 / 火山口）
        ↓
追踪阶段（3–5 分钟）：脚印、断枝、血迹、粪便、爪痕
        ↓  读痕迹判断目标的体型、状态、行进方向
遭遇阶段：巨兽有三个战斗阶段，会逃跑换区
        ↓
部位破坏：角、前爪、尾巴、背甲各自有独立耐久
        ↓  破坏不同部位 = 削弱不同能力 + 决定掉落素材
讨伐 → 剥取（有时限，剥取时其他小怪会来抢食）
        ↓
返回营地 → 锻造 / 强化 → 解锁更高级契约
```

## B.3 视角与画面

| 参数 | 数值 |
| --- | --- |
| 视角类型 | **第一人称** |
| FOV | 90°（默认，可调 70–110） |
| 武器呈现 | 屏幕下方 1/3，大幅度挥砍动画（重武器有明显的起手与收招硬直） |
| 相机动态 | 挥砍时轻微俯仰、受击时强震动、被巨兽甩飞时切换第三人称短镜头 |
| 特殊机位 | 讨伐终结时切入 2 秒过场机位（成本极低但商店页截图价值极高） |

**为什么选第一人称**：巨兽狩猎的核心体验是「体型压迫感」。第一人称抬头看向一只 8 米高的怪物，压迫感远强于第三人称。竞品 Hunters Inc 正是这个选择。副作用是玩家看不到自己的角色，所以时装系统的变现价值会降低——但这对我们不重要。

**Steam 画面参考**

| 参考作品 | 参考什么 |
| --- | --- |
| **Hunters Inc** | 第一人称近战 co-op 的整体框架、低多边形卡通质感（注意规避它「资产风格不统一」的差评） |
| **Deep Rock Galactic** | 四职业的功能分工、程序化洞穴的可读性、队友高亮系统 |
| **Monster Hunter: World** | 追踪痕迹的呈现方式、部位破坏的视觉反馈 |
| **Dragon's Dogma 2** | 攀爬巨兽身体的交互（可选进阶机制） |

## B.4 世界观与美术方向

**设定**：世界的边界正在被「巨兽」啃食。猎人公会用契约雇佣猎队去讨伐它们。你不是英雄，你是拿钱办事的。

**美术风格**：风格化低多边形卡通，饱和度中等偏高（与方案 A 的阴暗形成对比）。

关键成本策略：**内容密度集中在少数巨兽身上**。一只制作精良的巨兽（含 30+ 动作、4 个可破坏部位、3 阶段行为）的价值 >> 二十只平庸的杂兵。首发只要 5 只巨兽 + 8 种环境生物就足够撑起 15–20 小时。

## B.5 Steam 定位

| 项 | 内容 |
| --- | --- |
| 主标签 | Co-op, Hunting, Monster Hunter-like |
| 副标签 | First-Person, Crafting, Fantasy, Procedural Generation, Online Co-Op, PvE |
| 建议价格 | 抢先体验 $14.99 |
| 竞品实证 | Hunters Inc：$11.99 / 70% 好评 / 107 条评论。它的好评率偏低说明这个位置**还没有被做好** |
| 目标受众 | 想要 Monster Hunter 的快感但不想花 100 小时学系统的玩家；DRG 玩腻了想换题材的 co-op 团 |

## B.6 内容体量

**垂直切片**：1 只巨兽（3 阶段、4 可破坏部位）、1 张狩猎场、2 职业、追踪系统、剥取与锻造闭环

**EA 首发**：5 只巨兽、4 张狩猎场（各有天气变体）、4 职业、装备树 3 系各 8 级、AI 猎犬同伴（单人玩家的追踪辅助与救援）

## B.7 技术实现路径

联机是这个方案的必需项而非可选项，架构必须一开始就按联机设计：

| 模块 | 方案 |
| --- | --- |
| 联机 | Unity Netcode for GameObjects + Steam Networking Sockets 传输层；主机权威，Steam 中继免费 |
| 巨兽 AI | 分层状态机（阶段 → 行为组 → 具体招式），配合部位耐久系统驱动阶段转换 |
| 追踪系统 | 痕迹点在生成狩猎场时沿巨兽的历史路径播撒，玩家交互后在小地图留标记 |
| 部位破坏 | 每部位独立碰撞体 + 耐久，破坏后切换 mesh 变体并禁用对应招式 |

## B.8 可行性评估

| 维度 | 评分 | 说明 |
| --- | --- | --- |
| 美术资产可程序化产出 | ★★☆☆☆ | **最大短板**：巨兽的模型与动画很难程序化产出，需要采购资产或投入大量手工调整 |
| 无 GPU 环境可开发性 | ★★★☆☆ | 开阔地形 + 大体型怪，软件渲染压力大于方案 A |
| 玩法系统复杂度 | ★★★☆☆ | 追踪与部位破坏是纯逻辑，可控 |
| 联机复杂度 | ★★☆☆☆ | 4 人同步一只大型怪物的动画状态，是本方案技术难度最高处 |
| 单人可完整体验 | ★★★★☆ | 需要 AI 同伴支撑，参考 DRG: Rogue Core 的做法 |
| 商业天花板 | ★★★★☆ | co-op 传播力强，但竞品 Hunters Inc 已占位 |

## B.9 风险与对策

| 风险 | 对策 |
| --- | --- |
| 巨兽动画质量不足会毁掉整个体验 | 采购高质量巨兽资产（Unity Asset Store 有大量可商用的怪物包），把自研精力放在行为逻辑而非模型上；或者把巨兽设计成**几何抽象体**（如由碎石与光核组成的构造体），这类形态的动画可以用程序化 IK 与物理驱动，绕开手工动画 |
| 联机同步在无 GPU 环境难以测试 | 用 Unity 的多进程本地联机测试（同一台机器起 2 个无头客户端 + 1 个主机），全部在 batchmode 下跑自动化测试 |
| 与 Hunters Inc 正面撞车 | 差异化点选「部位破坏 + 追踪深度」，走比它更硬核的路线，价格站在它上方 |

# 方案 C：《Hunter: 兽径》（代号 Wendigo Trail）

> 推荐指数：★★★★☆（最低风险，最快上架）

## C.1 一句话定位

PS1 复古画风的**单人氛围恐怖狩猎**：你带着一把只有六发子弹的猎枪进入雪林去猎它，走了两小时之后你发现——被追踪的一直是你。

## C.2 核心玩法循环

```
序章：接受一份看似普通的除害委托
        ↓
┌─→ 白天：追踪痕迹、设陷阱、收集稀缺资源（子弹 / 燃油 / 绷带）
│       ↓
│   黄昏：必须回到猎屋，点燃火炉（火 = 唯一安全区）
│       ↓
│   夜晚：它来了。不能战斗，只能藏、跑、用火与噪音驱赶
│       ↓
└── 每一夜它变得更强，你的资源更少（共 5 夜）
        ↓
第五夜：身份反转 —— 你必须主动出去猎它，而火炉已经烧完
```

**这个循环的价值**：它把「资源管理」「追踪」「恐怖」三件事绑成一个不断收紧的螺旋，而实现成本极低——没有联机、没有大量敌人类型、没有复杂战斗系统。整个游戏只需要**一个**做得极好的敌人。

# 推荐与决策

## 推荐排序

**第一推荐：方案 A《金雾猎场》**

理由按权重排列：

1. **赛道数据最优**。Extraction Shooter 在全表中是唯一同时满足「竞品少（106 款）」「中位收入高（$33K）」「参与度极高（中位 672 条评论）」的标签。评论数直接喂养 Steam 算法，这是独立游戏唯一买不到的资源。
2. **规避了竞品的致命短板**。《雾影猎人》以字节量级的资源投入，依然在服务器与优化上被大量差评。我们用 AI 猎金人替代真人对手，把这个战场整个绕开，同时保留搜打撤 95% 的核心快感。
3. **美术方案与开发条件天然契合**。金雾既是世界观、又是玩法机制、又是渲染预算控制器。它让「无 GPU 开发」「无美术团队」「风格统一」三个约束同时解决，而不是妥协。
4. **代号契合**。玩家角色就叫猎金人（Hunter）。
5. **结构已被 2026 年市场验证**。「局内 run + 局外基地成长」的双层结构在 Grain Rot（2026-08-07 上线，Very Positive）上刚刚再次验证。

**第二推荐：方案 C《兽径》**

如果你希望**先用最低风险跑通一次完整的 Steam 发行流程**（建页面、过审、定价、发售、收款），方案 C 是最优选择：体量最小、美术门槛最低、无联机、有明确终点。可以把它当作方案 A 的前置练兵，两者不冲突。

**方案 B** 的巨兽资产是硬门槛，除非接受采购资产。
**方案 D** 的手感风险在缺乏真人试玩循环的条件下过高。
**方案 E** 在无 GPU 环境下的画面验证困难最大。

## 需要你拍板的五个决策项

1. **选哪个方案？** 或者要不要走「先 C 后 A」的两步路线（先用小体量跑通发行链路，再做大的）。

2. **联机要不要做？** 方案 A 可以做成纯单人，也可以二期加 3 人 co-op（用 Steam 免费中继，不自建服务器）。加联机会让整体开发量增加约一半，但 co-op 是 Steam 上最强的曝光杠杆之一。

3. **发行策略：抢先体验还是完整发行？** EA 可以更早拿到收入与反馈，但需要承诺持续更新；完整发行一次性交付，但对首发内容量要求高。

4. **Steamworks 账号什么时候办？** 这是硬阻塞项：$100 押金、税务与银行信息、身份验证，且商店页公开后要等 30 天才能发售。我无法代办，需要你用自己的身份完成。建议在选定方案后立刻启动，与开发并行。

5. **内容尺度？** 方案 A 和 C 都涉及暴力与恐怖元素。如果计划上中国区，题材尺度需要收敛（例如去掉血腥的肢解表现）。请明确目标区域。
