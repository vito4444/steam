# 遮挡与贴合规则表（CERE-14）

这份文档描述 PixelFit 分层渲染里「谁盖谁、哪一块要裁掉、怎么贴合、用户怎么手动改」。

规则本体在 `src/shared/occlusion.ts`，**是数据不是代码**：合成器
（`src/renderer/src/render/canvas2d.ts`）只负责执行，不做任何判断。加品类、改穿法
只动这张表，或者在素材库根目录放一份 `occlusion.json` 覆盖（见 §8）。

所有长度单位都是**肩宽的倍数**（`shoulderW`），不是画布像素 —— 换一版底图、换一种
画布尺寸，规则不用重标。锚点取值来自底图包 manifest；肩宽是从底图 alpha 轮廓实测的。

---

## 1. 画序（z-order）

能靠画序表达的遮挡就不做像素运算。z 大的后画，压在 z 小的上面。

| z | 槽位 | 说明 |
|---:|---|---|
| 0 | background | 舞台背景 |
| 10 | hair_back | 发型（后） |
| 15 | cape | 披风 |
| 20 / 22 | body / face | 底图人体、五官 |
| 24.5 | 底图内衬层 | 底图包自带 |
| 25 | underlayer | 内层 |
| **40** | **bottom** | 下装 |
| **44** | **legwear** | 袜 / 打底 —— **在裤之上** |
| **46** | **shoe_base** | 鞋 —— **在袜之上** |
| 48 | shoe_shaft | 靴筒（素材单独出这一层时用） |
| 50 | dress | 连衣裙 |
| 55 | top | 上装 |
| 65 | belt | 腰带 |
| **70** | **outer** | 外套 —— **盖上装** |
| 72 | neckwear | 围巾 |
| 80 | gloves | 手套 |
| 85 | bag | 包 |
| 90 | hair_front | 发型（前） |
| 95 | headwear | 帽饰 |
| 100 | eyewear | 眼镜 |

粗体是 issue §1 点名的三条硬要求。第四条「裤脚盖鞋帮」和 `shoe_base > bottom`
方向相反 —— 画序表达不了，交给 §3 的成对挖除。

逐件还能用 `z_offset`（−4 ~ +4）微调，画布上选中一件后按 ▲▼ 即可，改动记进 Look。
渲染时槽位的结构层级始终从当前 `OcclusionConfig.order[slot]` 读取；逐件微调还会被限制在
相邻结构层级中点形成的非重叠区间内。即使 `bottom / legwear / shoe_base` 只相差 2～4，
或自定义规则把 `top / outer` 设得很近，微调也不能越过相邻槽位。调用方传来的旧 z
只能还原出这段区间内的逐件偏移，不能颠倒规则表的结构顺序。

## 2. 互斥（`EXCLUSION_RULES`）

穿上 A 就必须脱掉 B。

| id | 穿上 | 清空 |
|---|---|---|
| `dress_clears_separates` | dress | top, bottom |
| `top_clears_dress` | top | dress |
| `bottom_clears_dress` | bottom | dress |

## 3. 成对挖除（`OCCLUSION_RULES`）

画序表达不了的遮挡：用**上层的轮廓**在**下层**身上挖掉一块 alpha。

字段：`over` 遮挡方 / `under` 被遮方 / `band` 生效的 y 区间 / `growK` 挖之前把遮挡方
轮廓外扩多少 / `featherK` 交界羽化 / `when` 生效条件。

| id | over → under | 区间 | 条件 | 作用 |
|---|---|---|---|---|
| `hem_over_shoe` | bottom → shoe_base | 踝线 +0.06 以上 | 总是 | **裤脚盖鞋帮**。鞋在裤之上（z），但踝线以上被裤子挖掉，靴筒才不会穿出裤腿 |
| `hem_over_boot_shaft` | bottom → shoe_shaft | 同上 | 总是 | 同上，单独出的靴筒层 |
| `tuck_top_into_bottom` | bottom → top | 腰线 −0.015 以下 | 塞衣角 = 塞进去 | **上装下摆压在下装腰线之下** |
| `tuck_underlayer_into_bottom` | bottom → underlayer | 同上 | 同上 | 内层跟着一起塞 |
| `dress_over_legwear_top` | dress → legwear | 胯 +0.1 以上 | 总是 | 打底裤腰头不从裙腰上方冒出来 |

`growK` 为什么必须 >0：两层边缘完全重合时，抠图各自的半透明过渡叠起来会留下一条
一像素的亮缝，比不挖还显眼。

## 4. 区间守卫（`REGION_GUARDS`）

一件衣服只允许出现在身上的哪一段，段外的像素直接裁掉。

| id | 作用槽位 | 保留区间 | 作用 |
|---|---|---|---|
| `no_garment_on_face` | top / underlayer / dress / outer / cape / belt / bottom / legwear | 下巴 −0.02 以下 | 领口、帽兜贴过头会直接盖住脸 |
| `scarf_below_chin` | neckwear | 下巴 +0.005 以下 | **围巾不许糊脸** —— `fig-05` 里围巾盖了半张脸就是缺这一条 |
| `headwear_above_chin` | headwear | 下巴 +0.02 以上 | 帽子不许垂到下巴以下 |
| `eyewear_on_face` | eyewear | 头顶 ~ 下巴 | 眼镜只在头部范围内 |
| `shoes_on_ground` | shoe_base | 裆线 +0.05 以下 | 抠图带上裤腿时不至于整条腿变成鞋；放到裆线而不是膝盖，是为了给过膝长靴留出靴筒 |

多条命中同一槽位时取**交集**（区间取更紧的那一头）。

## 5. 身体遮罩（`MASK_POLICY`）

把衣物超出身体轮廓的部分裁掉 —— 这是「衣服飘在空中」的正面解药。

遮罩来源，按优先级：

1. **底图包 manifest 的 `mask` 字段**（CERE-13 的贴身底图会给）。格式：

   ```jsonc
   {
     "pack": "cere13-fitted-f01",
     "canvas": { "w": 1152, "h": 2304 },
     "anchors": { "shoulder_l": { "x": 300, "y": 520 }, "...": {} },
     // 人体轮廓的 alpha 图，画布坐标系与底图一致。
     // 只用 alpha，RGB 是什么颜色无所谓（纯白最省事）。
     // 手臂、腿要与躯干**分开**保留各自轮廓，别糊成一个人形色块 ——
     // 「袖子飘在体侧」正是靠手臂与躯干之间那道缝裁掉的。
     "mask": "body_mask_f01.png",
     "tones": [],
     "layers": []
   }
   ```

   也可以写成完整层对象 `{"file": "...", "z": 0, "mode": "normal"}`，效果一样。

2. **回落：底图人体层自己的 alpha**。底图本来就是透明底的人形，alpha 就是轮廓。
   精度差一档（衣物遮住的部分量不到），但**链路现在就能跑通** —— 本轮交付的所有
   对比图都是靠这条回落出的。CERE-13 的 `mask` 落到 `library/base/<体型>/` 之后
   自动接管，应用侧不用改代码。

每个槽位允许超出轮廓多少不一样：

| 槽位 | 外扩量（肩宽倍数） | 裁切区间 | 说明 |
|---|---:|---|---|
| top | 0.13 | 全高 | 摊平拍的袖子对不上手臂时直接削掉，好过悬在体侧 |
| underlayer | 0.06 | 全高 | 贴身，宽松量最小 |
| outer | 0.17 | 胯 +0.45 以上 | 宽松量最大，长大衣下摆往下放开 |
| dress | 0.12 | 胯 +0.04 以上 | 裙摆是要外扩的，裁了就变成紧身裙 |
| bottom | 0.14 | 裆 +0.2 以上 | 只裁腰胯段，裤腿往下放开 |
| legwear | 0.07 | 踝 +0.05 以上 | 贴身 |
| cape | 0.30 | 胸线以上 | 只在肩胸段收一下 |
| belt | 0.10 | 全高 | 贴腰 |
| 围巾 / 包 / 鞋 / 手套 / 帽 / 眼镜 | — | 不裁 | 它们本来就挂在体外 |

**裁切区间的边界必须是渐变**（`featherK` 给到 0.13–0.16），硬边会在裙摆上留一条
横切线，比不裁还显眼。

外扩用 12 方向偏移画一圈实现（`render/mask.ts`），是形态学膨胀的廉价近似 ——
比高斯模糊准，模糊会让轮廓一起变虚，裁出来的边是糊的。

## 6. 执行顺序

`canvas2d.ts` 按下面的顺序做，顺序不能换：

```
每件各自处理（第一轮）
  1. 不透明度补偿   抠图欠实的素材把自身多叠一两遍（见 §9）
  2. 边缘羽化       模糊过的自身当掩膜再乘一次 alpha
  3. 区间守卫       §4
  4. 身体遮罩       §5
互相处理（第二轮）
  5. 成对挖除       §3，用的是别人**第一轮之后**的轮廓
绘制
  6. 接触阴影 + 按 z 叠图
```

为什么必须分两轮：遮挡关系里 z 高挖 z 低（裙挖打底裤）和 z 低挖 z 高（裤挖鞋）
**同时存在**，没有任何一个单一顺序能同时满足。分两轮之后结果与处理顺序无关。

接触阴影是从**裁完的**精灵图算的，所以被挖掉的部分不会留下没主的影子。

## 7. 贴合校准

### 7.1 自动解

位置按**可穿戴语义点对齐**，而不是一律拿整张抠图包围盒贴单点：

- `top` / `outer` / `dress`：素材肩点对齐模特左右肩点，肩点行对齐肩线；
- `bottom`：素材腰头两端的中点对齐腰线，但横向尺度以胯宽为覆盖目标；
- `neckwear`：第一行实际材质（`top_edge`）至少停在下巴以下 `0.1 × shoulderW`；
- `shoe_base` / `shoe_shaft`：`top_edge → hem` 映射到「踝线向上重叠 `0.04 × shoulderW`
  → `foot_base`」，既包住脚踝交界，也落到脚底。

成对 landmark 除了素材包明确标注的值，也可采用导入器实测值，但必须通过坐标范围、
最小跨度与左右高度差校验；没有通过就回落到槽位锚点与包围盒。

大小要难得多，因为真实照片的包围盒宽度**语义随拍法而变**：

- 摊平拍的毛衣 → 包围盒宽度是**袖展**，比肩宽大一倍多
- 挂着拍的卫衣 → 包围盒宽度只有半个胸宽
- 手提包 → 按行量出来的「肩线」其实是提手，只有包身的三分之一

所以缩放两路并给，再互相夹（`render/fit.ts`）：

| 驱动 | 用于 | 算法 |
|---|---|---|
| 按衣长 | top / underlayer / outer / dress / cape | 身上那一段的长度 ÷ 素材的上沿→下摆，再被「按宽度」解夹在 [0.7×, 1.45×] 内 |
| 按宽度 | bottom / legwear / belt / shoe / 配饰 | 该段身体实测宽度 × 版型宽松量 ÷ 素材参照宽度 |

| 槽位 | 宽度参照 | 系数 | 竖直锚点 |
|---|---|---:|---|
| top | 左右肩点 | 1.00 | 肩点对肩点（衣长覆盖 肩线→胯） |
| outer | 左右肩点 | 1.00 | 肩点对肩点（衣长覆盖 肩线→胯+0.3） |
| dress | 左右肩点 | 1.00 | 肩点对肩点（衣长覆盖 肩线→膝） |
| bottom | 腰头点对，目标胯宽 | 1.06 | 腰线 |
| legwear | 胯宽 | 0.99 | 胯 |
| shoe_base | **双脚站距** | 1.35 | 踝线重叠 → `foot_base` |
| neckwear | 肩宽 | 0.66 | **下巴 + 0.1 肩宽**（按第一材质行） |
| bag | 肩宽 | 0.50 | 胯，横向偏 0.58 肩宽 |
| headwear / eyewear | 头宽 | 1.22 / 0.94 | 眉眼线 |

两处容易踩的坑，都已经堵掉：

- **鞋的宽度参照是双脚站距，不是单只脚踝** —— 一张鞋素材里通常是两只鞋并排，
  按单脚踝缩会小掉一半。
- **成对语义点要过可信度检查**。上装肩点、下装腰点即使是导入时量出的，只要范围、
  跨度和左右高度差合理就参与贴合；包、围巾等不声明成对对齐的槽位不会误把提手或
  碎屑当肩线。

横向与纵向分别输出 `scaleX` / `scaleY`。自动解允许为了「肩宽 + 衣长」或
「鞋宽 + 踝到脚底」而采用不同轴比例；用户的 `fit.scale` 同时乘两轴，只有
`fit.stretch_x` 额外乘横轴。Canvas2D 仍直接缩放原始 cutout 并做 alpha 合成，
不会重新量化颜色、重绘纹理或改写材质光影。

没有可信成对语义点时，成品宽度以肩宽的 2.4 倍兜底；所有路径的成品高度都不超过
画布的 1.2 倍。可信肩点 / 腰点优先保证语义覆盖，不用包围盒宽度上限破坏对齐。

### 7.2 塞衣角（按品类决定）

`defaultTuck()`：上装 / 内层的 `attributes.length` 是 `crop` 或 `waist` 时默认
塞进腰里，其余默认放下来。用户可在贴合面板逐件改，改动记进 Look 的
`tuck_overrides`。

### 7.3 手动微调

分层贴图相对生成式试穿唯一的优势就是这类微调**可复现、可存档**，所以做实了：

| 操作 | 手势 | 存进 Look 的字段 |
|---|---|---|
| 移位 | 在模特身上直接拖这一件（按 alpha 命中，不是包围盒） | `fit_overrides[id].dx/dy` |
| 缩放 | 选中后滚轮，或贴合面板的滑杆 | `fit_overrides[id].scale` |
| 横向形变 | 贴合面板滑杆（限制 ±12%） | `fit_overrides[id].stretch_x` |
| 上下层级 | 画布工具条 ▲▼，或贴合面板 z_offset 滑杆 | `z_overrides[id]` |
| 塞衣角 | 贴合面板分段控件 | `tuck_overrides[id]` |
| 复位 | 画布工具条「复位」 | 清除该件的全部覆盖 |

位移单位是**肩宽的倍数**而不是画布像素 —— 换一版底图、换一种画布尺寸，已存的
微调不会失准。

引擎接口上这是两个**可选**能力（`hitTest` / `fitUnit`）。生成式引擎给不出「这个
像素属于哪一件」，会如实返回 null，界面自动收起画布上的拖拽，而不是留一个点了
没反应的假交互。

## 8. 运行期覆盖规则表

素材库根目录（设置页里能看到路径）放一份 `occlusion.json`，重启应用生效：

```jsonc
{
  // 改画序
  "order": { "legwear": 38 },
  // 按 id 改单条规则，或停用
  "occlusions": {
    "tuck_top_into_bottom": { "band": { "from": { "anchor": "waist", "offsetK": 0.02 } } },
    "dress_over_legwear_top": { "disabled": true }
  },
  "guards": { "shoes_on_ground": { "featherK": 0.05 } },
  // 改身体遮罩策略
  "mask": { "top": { "dilateK": 0.2 } },
  // 加品类时追加新规则
  "addOcclusions": [{
    "id": "apron_over_dress", "over": "apron", "under": "dress",
    "when": "always", "note": "围裙盖裙子"
  }]
}
```

写坏了不会崩：解析失败就退回内置默认表，并把原因带回界面。认不出来的键直接忽略。

## 9. 不属于遮挡、但渲染层顺手挡掉的一件事

CERE-10 有几件抠图是**整件半透明**的（manifest 里标了 `soft_matte_edges`，全图
没有一个 `alpha=255` 的像素，上限只有 180 左右），直接贴上去就是一件能看见身体的
衬衫。根因在素材侧（质检门槛是 CERE-12 的活），但渲染层不能装作没看见：

- 按素材自身 alpha 上限做一次保守的不透明度补偿（把同一张图多叠一两遍，alpha 按
  `1-(1-a)^n` 往上顶，**颜色一个像素都没动** —— 同色自叠还是同色）。
- 只在 alpha 上限明显偏低（<240）时才做，真·半透明的纱、蕾丝不受影响。
- 羽化掩膜先把内部顶实再模糊，否则本来就欠实的素材会被再乘薄一层。

这是权宜之计，不是修复。素材侧把 alpha 做实之后这段代码就是空跑。

## 10. 这条路线的效果上限

见 `docs/render-contract.md` §4。一句话：**规则解决的是「谁盖谁」和「可穿戴区域
放在哪」，解决不了「素材和模特不是同一次拍摄」**。源图袖子姿势、侧身透视和
褶皱方向不匹配时，双轴缩放只能对齐肩宽与衣长，不能把平铺姿势变成垂臂姿势；
不同来源的高光与阴影也原样保留，因为统一光照必然要改写要求保真的颜色与纹理。
