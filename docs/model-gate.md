# 模型缺失时的导入流程（CERE-64）

0.4.4 把 381.6 MB 的 ONNX 权重从安装包里拆了出去（496 MB → 184 MB，做法见
[`auto-update.md`](./auto-update.md) 第 1 节）。包体降了 62.9%，但代价是自动抠图
从开箱即用变成了「先去设置页点一次「下载识别模型」」。

成员没做这一步。反馈原话是：**「目前还是识别不到，无法自动抠图」**。

这不是使用者的问题。一个核心功能依赖一个藏在设置页里、没人告诉你要做的手动动作，
是产品设计问题。0.4.9 改的就是这个。

## 一条规矩

**用户点「从照片导入」的时候，模型缺失就地解决，不要把人赶去设置页。**

他点的是「导入这张照片」，不是「下载模型」。所以下完必须**继续他原本的动作**，
而不是让他下完再走一遍流程。

## 缺模型不再把按钮变灰

0.4.4–0.4.8 的做法是 `disabled={!pipeline.automatic}`。灰按钮只是把失败提前，
用户仍然不知道该干什么 —— 界面上没有任何东西告诉他「差的是一个下载」。

现在的判断收在 `src/renderer/src/features/import/model-gate.ts` 的 `gateDecision()`：

| 状态 | 决策 | 界面行为 |
| --- | --- | --- |
| 模型就绪 | `run` | 直接干活 |
| 运行时在、模型缺失 | `gate` | 弹出下载说明，下完自动续跑 |
| 本地识别运行时没装 | `unavailable` | 如实说明并指向透明底手动入口 |

只有第三种才点不动 —— 那种情况下多少模型都救不了。

三个入口共用同一扇门（`ModelGateProvider.runWithModel()`）：导入页「选择照片并
自动识别」、衣橱空态的导入按钮、基底页「上传模特照片」。三条路失败的原因是同一个，
就不该有三种说法。设置页那个入口保留，但不再是唯一路径。

**已经有透明底 PNG 的用户一个字节都不用下。** 那条路不碰模型，逻辑没动。

## 弹窗里说什么

一屏说完，再往下就没人读了：

- 为什么需要（识别衣物、自动抠图靠两个本地模型）、多大（381.7 MB）；
- **只下一次**，以后升级版本都不会再下这部分；
- 下完**自动继续刚才的导入**；
- 下载期间能做什么：点「后台下载」先去衣橱逛，或者直接导入透明底 PNG；
- 落盘位置和校验方式。

下载中显示进度、速度、剩余时间，可以「取消下载」。取消不算故障：已经下好的整块
文件保留着，下次接着下不会从头再来。

## 失败要分类

「下载失败」对用户等于没说 —— 断网、磁盘满、校验不过，三种情况的下一步完全不同。
`classifyFailure()` 把原始异常归到四类，每类在共享层配一句能照做的话
（`MODEL_PACK_HINT`），原始报错留在下面小字里给排查用：

| 分类 | 触发 | 下一步 |
| --- | --- | --- |
| `network` | ENOTFOUND / ECONNRESET / HTTP 4xx-5xx… | 检查网络或代理；或打开 Releases 页面手动下载 |
| `disk` | ENOSPC，或下载前的空间预检没过 | 腾出至少 400 MB |
| `checksum` | 字节数不符 / MD5 不匹配 | 文件已删，直接重试；另给「清空重下」 |
| `canceled` | 用户点了取消 | 不是故障，不显示错误 |

取消的判断排在网络之前：abort 掉的 fetch 报的是 `AbortError`，按关键字容易被归成
网络故障，但用户自己点的取消不是故障。

磁盘空间在**下载开始前**查（`statfs`，留 64 MB 余量），而不是下到 90% 才 ENOSPC。

## 残缺文件自动清理

上一次下到一半被杀进程（关窗口、断电、任务管理器结束进程）会留下 `.part`；
老版本或手动拷贝也可能留下字节数不对的半个模型。这些残留会让之后**每一次**尝试
都从坏状态出发、每次都失败，而用户根本不知道 `.part` 是什么。

`sweepStale()` 在启动时和每次下载前各扫一遍外部资源包目录，删掉：

- `*.part` / `*.download`；
- `models.lock.json` 里有名字、但字节数对不上的文件。

已经下好的文件一个字节都不碰 —— 否则清理本身就成了新的 381.6 MB。
清掉了什么会如实显示在弹窗里，不静默删。

字节数对得上、内容却坏掉的情况（字节数校验拦不住内容损坏）另给一个入口：
「清空重下」= 删掉整个外部资源包再下一遍。

## 版本号

成员报「识别不到」时，第一个要问的就是「你装的是哪一版」。所以版本号常驻标题栏，
设置页标题旁边再写一次，不用教对方去哪儿找。

## 取证

`PixelFit.exe --model-gate-evidence`（配合 `PIXELFIT_ROOT` 指向一个干净目录）跑的是
真窗口真流程：干净 profile 下模型资源包目录是空的，点的是界面上那几个真按钮，
381.6 MB 是真的从 GitHub Releases 下下来的，续跑的那次导入是真的把照片喂给本地管线
抠出来入库的。唯一的区别是「谁来点」。

输出 `01-first-run.png` … `05-wardrobe.png` 加 `report.json`（前后素材数、资源包状态、
版本号）。选图框是原生窗口、脚本点不动，所以这一个模式下允许用
`PIXELFIT_IMPORT_PHOTOS` 指定照片 —— 换掉的只有「谁选的文件」，之后的抠图、质量门、
入库每一步都是真的。正常运行时这个分支不存在。
